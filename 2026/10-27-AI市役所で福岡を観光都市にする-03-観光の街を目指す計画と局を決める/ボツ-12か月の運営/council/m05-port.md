# m05 港湾空港局の案

## 案1: 乗客に対してバスが多すぎる路線の台数を減らし、乗客の多い路線に回す

### 施策

- 案の id: port-1
- 施策: 路線ごとの台数の割合(set_transport_line_budget)を5路線で変える。減らすのは路線136(Bus Line 28、台数188、乗客88)、路線139(Bus Line 38、台数101、乗客29)、路線127(Bus Line 37、台数57、乗客21)を、予算200%から180%へ。増やすのは路線3(Bus Line 1、台数23、乗客158)と路線88(Bus Line 3、台数15、乗客159)を、予算100%から120%へ。街全体の予算(set_budget)は動かさない
- 議決: 予算

### 実行計画

- 実行可否: 確認済み
- 対象と操作順:
  1. `set_transport_line_budget(line=136, percent=180)`
  2. `set_transport_line_budget(line=139, percent=180)`
  3. `set_transport_line_budget(line=127, percent=180)`
  4. `set_transport_line_budget(line=3, percent=120)`
  5. `set_transport_line_budget(line=88, percent=120)`
  - 引数の line は list_transport_lines の line(内部の番号)。画面の番号 number ではない。5路線とも、list_transport_lines で今の budget(200 / 200 / 200 / 100 / 100)と台数を確かめた
  - 変更は各路線 ±20 の範囲内(予算の上限の型どおり)。percent は 10〜300 の範囲内
- 設置条件の確認: 該当なし(建設なし)。バスの車庫(Bus Depot 30483、46613)は maxVehicles -1 で、台数の上限に当たらないことを `transport_depots` で確認
- 接続工事: 不要
- 予備候補: なし(路線の変更だけ。ほかの路線は、この案の中では動かさない)
- 中止する条件: (a) 5つの呼び出しのどれかが断られた場合は、断られた路線だけを外し、残りは実行する。(b) 実行の前に路線136、139、127 の台数が188 / 101 / 57 から大きく動いていたら(予算の変更で台数が変わっていない)、見送る。

### 期待する効果

- 改善の見込み: バスは1,830台あり、そのうち694台が渋滞の中で詰まっている(`vehicles_stuck` kind=bus)。1路線で台数188の路線136は乗客88で、1台あたりの乗客が少ない。台数を減らせば、道の上のバスが減り、6-3 の流れと止まった車に効くと見込む。一方、乗客の多い路線3と88に台数を回すと、乗客の取りこぼしが減る見込み。
- 数値と期限: 路線136 は台数188 → 約171(予算比の概算)、路線139 は101 → 約92、路線127 は57 → 約51、路線3 は23 → 約28、路線88 は15 → 約18。台数の合計は約-27台。週の維持費は、バス1台あたり約11.5 / 週(`economy_breakdown` の PublicTransportBus 支出 22,111 ÷ バスの車庫の台数 1,917 の概算)で、約 -300 / 週の見込み。期限は2か月目の月末(30日目)。
- 確認方法: `list_transport_lines`(line 136、139、127、3、88 の vehicles と passengers)と、`vehicles_stuck`(kind=bus、byState の Blocked 系の数)。今の値: 台数 188 / 101 / 57 / 23 / 15、乗客 88 / 29 / 21 / 158 / 159、バスの Blocked 系は 694(Congestion+OnRoad+Blocked)、バス全体 1,830。
- 不確かな点: 台数の減りが道の詰まりを減らすかは、量を見積もれない。乗客は、台数を減らした路線で減るかもしれない。バス総数の 1,830 台は、ほかの路線の増減で動くため、路線の変更だけの効果は分けにくい。量は見積もれない。確認する変化は、対象の路線の乗客と台数、バスの Blocked 系の数の変化。
- 試し: 試し。仮説: 乗客に対して台数が多い路線を減らすと、道の上のバスが減り、バスの Blocked が減る。測る数は、路線136、139、127 のバス台数とバスの Blocked 系。場所は路線の経路(バス全体)。基準は今の値(バス Blocked 系 694、バス全体 1,830、路線136の台数 188)。編成方針の「分からないこと」の項目には当たらない。

## 判断の根拠

- 担当の数字のうち、6-3 の流れ(54、目標60)は、バスの台数の多さが一因と見込んだ。バスの Blocked 系 694 台(全体1,830台の38%)が詰まりの中にあり、台数の多い路線136(台数188、乗客88)は1台あたりの乗客が少ない。乗客の多い路線3と88は台数が少ない(23 / 15 台)のに乗客が多く(158 / 159)、台数を回す先になる。
- 案は1件にした。路線の台数の配分は、減らす路線と増やす路線を一つの手にまとめ、同じ手の言い換えにしない。件数を埋めるための案は出さない。
- 8-1(貨物駅28755の敷地内の待ち530台)は、案を出せなかった。原因は調査で確かめる。13893 は稼働しているが、トラックも列車も行き先にしていない。新しい貨物駅を置く案は、接続と効きが確かめられないため出さない。
- 政策は、交通に効く候補(FreeTransport、HeavyTrafficBan)を比べた。FreeTransport は運賃の収入が 0 になり、公約3(週の収支)に響くので外す。HeavyTrafficBan は 8-1 の荷を運ぶトラックを止めるので外す。
- 実行の条件は、5路線の line と今の budget を list_transport_lines で確かめた。車庫の上限はない(transport_depots)。
