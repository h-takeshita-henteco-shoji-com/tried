## 案1: 満杯の埋立地25590を空け、工場群のごみを近くで受ける(試し)

### 施策

- 案の id: health-1
- 施策: 満杯の埋立地 25590(座標 3900,-575)を空にし、ごみの印の工場群(中心 3512,-600 の周り)の収集先を近くにする。道具は `empty_building`
- 議決: 要らない

### 実行計画

- 実行可否: 確認済み
- 対象と操作順:
  1. `empty_building` id 25590、active=true(空にする)。費用0、維持費の増え0
  2. 次の見回り(10日目・20日目)で `services` の garbage.full と `buildings_near` の Garbage を確かめる
  3. 月末に 25590 を `empty_building` id 25590、active=false で戻す(受け入れを再開する)
- 設置条件の確認: 対象の 25590 は `buildings_near`(x 3900, z -575)で problem LandfillFull を確認。同じ道具での空にする操作は、m01-4 で既に実施済み(満杯は減った)
- 接続工事: 不要
- 予備候補: 使わない。新しい埋立地は、この月は場所の確認ができていない(下の捨てたもの)
- 中止する条件:
  - 空にした後、ごみの印(`complaints` の Garbage)が28より増える、または `buildings_near` の Garbage(中心 3512,-600、半径300)が8より増えたら、月末を待たずに active=false で戻す
  - 収集車の渋滞が増え、`vehicles_stuck` の garbage で 3631,-254 付近の台数が増えたら戻す(m01-4 の失敗と同じ形)

### 期待する効果

- 改善の見込み: 工場群の近くの満杯の埋立地が受け入れるため、工場の収集車が遠くの焼却場まで行かなくてよくなると予想する。確認した事実は、25590 が満杯で、工場群の garbage の印が 8 棟(半径300)あること。
- 数値と期限: `buildings_near` problem=Garbage の、中心(3512,-600)半径300の棟数。今の値は 8。予想は 3 以下(量は見積もれない)。期限は月末(30日目)。ごみの印の街全体の数は今 28(目標0)。
- 確認方法: `buildings_near`(x 3512, z -600, radius 300, problem "Garbage", brief true)と `complaints`(Garbage の棟数)。同じ条件で今の値と比べる。収集車の渋滞は `vehicles_stuck`(kind garbage, limit 10)。
- 不確かな点: 空にした中身は、ほかの埋立地へ運ばれる。m01-4 では遠い焼却場へ運ばれて、道の渋滞が増えた。今回も運び先の道が詰まると、効かないか悪化する。効果の量は見積もれない。
- 試し: あり。仮説: 工場群の近くの満杯の埋立地が受け入れを止めているため、工場のごみが収集されない。測る数: `buildings_near` の Garbage 棟数(中心 3512,-600、半径300)と、街全体の `complaints` の Garbage。場所: 工場群(3512,-600 の周り)。基準: 棟8、街全体28。編成方針の「満杯の埋立地を空けると、なぜごみの印が増えたのか」の項目に当たる。

### 費用

- 建設費: 0
- 週の維持費の増え分: 0(`empty_building` は費用を増やさない)

### 戻せるか

戻せる。active=false に戻せば、埋立地は受け入れを再開する。議決は要らない。

## 案2: 社会のリサイクル(Recycling)をかけ、住宅低の税率を1上げる

### 施策

- 案の id: health-2
- 施策: 政策 Recycling を街全体にかける(ごみ -15%、住宅の税収 -5%)。その分を補うため、住宅(低)の税率を9から10にする
- 議決: 税

### 実行計画

- 実行可否: 確認済み
- 対象と操作順:
  1. `set_tax` target "residential_low", rate 10(現在の値9から+1。±2の範囲内)
  2. `set_policy` name "Recycling", active true(週の費用0を `list_policies` で確認済み)
  3. 見回り1(10日目)で `city_info` の週の収支と、`economy_breakdown` の Residential の収入を見る
- 設置条件の確認: 政策 Recycling は `list_policies` で有効でないことと、costPerWeek 0 を確認。税率の変更は `tool-reference.md` の `set_tax` の引数(rate 1〜29)で確かめた。建設は無いので、敷地・接続の確認は該当なし
- 接続工事: 不要
- 予備候補: なし(税の補いは住宅(低)1だけ。ほかの税は動かさない。Recycling の代わりの政策は出さない)
- 中止する条件:
  - 見回り1で週の収支が 0 を下回る(赤字)なら、`set_tax` residential_low rate 9 と `set_policy` Recycling active false で戻す
  - 住宅の需要(`city_info` の需要の住宅)が月初の25より下がったら、税率を9に戻す

### 期待する効果

- 改善の見込み: Recycling は街全体のごみを15%減らすと、政策の説明にある。ごみの印 28 は収集の詰まりのほか、埋立地の満杯の量にも左右されるため、量が減ると印も減ると予想する。確認した事実は、Recycling が無効で週の費用0であること。
- 数値と期限: `complaints` の Garbage の棟数。今の値は 28(目標0)。予想は 15 から 20 の範囲(量は見積もれない)。期限は月末(30日目)。満杯の埋立地は今 8(`services` の garbage.full)。
- 確認方法: `complaints`(Garbage)、`services`(garbage.full の数と used)、`city_info`(週の収支)、`economy_breakdown`(Residential の収入)。今の値と同じ条件で比べる。
- 不確かな点: 住宅税の減りは -5% で、約 13,500/週(住宅税収 269,901 の5%、見積もり)。税率+1 で取り戻す額は、住宅(低)の税収の内訳が道具では分からないため、見積もれない。+12,000〜+21,000/週と仮定する(住宅税収の低の割合を40〜70%と置いた)。その場合の週の収支は -1,500〜+7,500 となり、下限では赤字になりうる。見回り1で確かめ、赤字なら戻す。税の変化が住宅の需要に響く可能性もある。
- 試し: なし(ごみの量の変化は、Recycling の説明の数値にもとづく予想)。

### 費用

- 建設費: 0
- 週の維持費の増え分: 0(政策の費用0。税率の変更は支出を増やさず、収入を変える)

### 戻せるか

## 判断の根拠

- 4-4(ごみ28、目標0)は、満杯の埋立地8と、工場群の収集車の渋滞が重なっている。工場群の近く(3900,-575)の埋立地 25590 は満杯で、工場の収集先が遠い。空にする操作は費用0で、m01-4 の経験から、中止条件(ごみ・渋滞の増加)を付けた。案1は試しとして出す。
- 案2は、Recycling の政策が費用0でごみの量を減らすが、住宅税収の5%(約13,500/週)を減らす。そこで住宅(低)の税率を1上げ、週の収支を黒字に保つ見込みにした。税の1上げは見積もりで、赤字の可能性が残るため、中止条件を付けた。
- 案は2件。4-4 の手は2つで、手の種類が違う(埋立地の運用と政策)。残りの手を件数のために足さない。
- 4-3 汚染(26、目標15)は、今月は確認できた手がない。焼却場 10351 の周りに汚染の印 9 棟が集まるが、移転先の候補を3か所で試し、道路・取り壊し・建物の重なりで断られた。そこで調査で、印の場所を見回りごとに追う。
- 政策は今月1つまでのため、Recycling だけを選んだ。HeavyTrafficBan は、貨物トラックを止めて8-1(港湾空港局)の流れを悪くするため、採らない。
