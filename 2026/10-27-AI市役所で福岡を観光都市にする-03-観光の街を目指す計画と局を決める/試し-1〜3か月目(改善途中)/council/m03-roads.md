  3. `upgrade_road(prefab="Small 4 Lane Road", points=[[80,-260],[80,-80]], tolerance=20, pay=true, demolish=false)`。matched 4 の区間をすべて上げる。費用 0

  - 1: `test_upgrade_road`(同じ引数)で matched 4、upgraded 4、skipped なし、cost 0、demolishedBuildings なし。`net_near`(-1684,-1000, r130)で区間の両端を確認
  - 2: `test_upgrade_road` で matched 4、upgraded 3、cost 0。31370 が ObjectCollision(相手 13510 の Basic 10m 区間、blocks=true)と SlopeTooSteep で飛ばされる。取り壊しはない。`buildings_near`(-1684,-1045, r120, problems_only)は0件

## 案2: (2110, 240) と (2110, 330) の交差点に信号を試す

- 案の id: roads-2

- 議決: 要らない

### 実行計画

- 実行可否: 確認済み(信号が付けられることは確認。費用は未確認)
- 対象と操作順:
  1. `set_traffic_lights(x=2110, z=330, active=true)`。交差点の node 30603(区間 3990、22887、26735)。junction_info で canEnableLights true、customLights false
  2. `set_traffic_lights(x=2110, z=240, active=true)`。交差点の node 24624(区間 5864、4374、9308)。junction_info で canEnableLights true、customLights false
- 設置条件の確認: `junction_info`(2110,330)と(2110,240)で、信号の付けられること、譲れの標識がないこと(yield false)を確認。区間は3本とも Small 4 Lane(junction_info の prefab)
- 接続工事: 不要
- 予備候補: 1か月後に効かなければ、信号を外す(`set_traffic_lights(x, z, active=false)`)。次に、譲れの標識を試す(`set_yield_sign(x=2110, z=240, segment=<junction_info の roads の segment>, active=true)`)。信号のある交差点には標識を付けられないので、先に外す
- 中止する条件: 信号を付けた後、`traffic` の blocked(x=2200, z=380, r200)が 45 より増えたら、2か所とも `set_traffic_lights(active=false)` で外す。週の収支が 13,313 から3,000以上下がったら、費用を確かめ、外す

- 改善の見込み: 三叉路で交互に通るようになり、南北の区間の途中で詰まる車が減る、と見込む。確認した事実は、(2101,278) と (2300,331) の止まり(3月4日の `traffic`)と、交差点に譲れの標識も信号もないこと
- 数値と期限: 基準は `traffic`(x=2200, z=380, r200)の blocked 45、congestion 86、flow 56。数値は見積もれない。期限は次の月末(4月末)。見回りは10日目と20日目に見る
- 確認方法: `traffic`(x=2200, z=380, radius=200)の blocked と blockedSpots、`city_info` の週の収支(13,313 が基準)。同じ中心と半径で比べる
- 不確かな点: 信号が効かず、待ちが増えるおそれ。道具は信号の建設費と維持費を返さない。週の収支の変化で確かめる
- 試し: 仮説は「三叉路の交互通行で、南北の区間の途中の止まりが減る」。測る数は `traffic`(x=2200, z=380, r200)の blocked(基準 45)と blockedSpots の (2101,278)(基準 27)。場所は (2110,240) と (2110,330) の間。基準は3月4日の値。編成方針の分からないことの「バス・道路の止まりの原因」に当たる
