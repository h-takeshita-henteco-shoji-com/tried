## 案1: 止まっている西の貨物駅40031を動かし、駅・港の待ちを分ける(試し)

### 施策

- 案の id: port-1
- 施策: 貨物駅40031(Cargo Center、座標 -1780, -1605。西の貨物駅)を動かす。今は TurnedOff。貨物駅28755(3449, -1555)に集中している貨物トラックの待ちを、西の駅へ分けられるかを試す。
- 議決: 要らない

### 実行計画

- 実行可否: 確認済み
- 対象と操作順:
  1. `set_building_active(id=40031, active=true)` で貨物駅40031を動かす。建設はしない。
  2. 10日後と20日後に、「調査」の道具で列車と止まったトラックの行き先を見る。
- 設置条件の確認:
  - `buildings_near`(x=-1780, z=-1605, radius=60): 40031 の grid は electricity / water / sewage がすべて true(必要分は来ている)。problems は TurnedOff のみ。放棄なし。
  - `transport_reach`: 40031 は outsideConnected=true、viaLaneConnection=true、outsideLines=0。外のつなぎ口まで線路で届いている。
  - 建物は既存のため、敷地と道路の新規確認は不要。
- 接続工事: 不要
- 予備候補: なし。13893(3529, -1555)と3940(2380, -1282)、4740(3955, -1270)も動いているが、列車が来ていない(`vehicles_stuck` train で行き先は28755のみ)。予備にしない。
- 中止する条件:
  - 10日目の見回りで、`vehicles_stuck`(kind=train)の byTarget に 40031 が1台も出なければ、`set_building_active(id=40031, active=false)` で止める。維持費を増やし続けないため。
  - 40031 の敷地で止まったトラックが増えたら(`vehicles_stuck` building=40031 で確認)、動かしたまま原因を調べる。

### 期待する効果

- 改善の見込み: 28755 は、11本の貨物列車すべての積み荷を受けて、敷地内のトラックを一か所で捌いている。492台が「WaitingSpace」(空き待ち)で敷地に残るのは、この駅の受け口が詰まっているためと見る。西の駅が列車の行き先に入れば、積み荷が2つの駅に分かれ、待ちが減ると予想する(予想。確認した事実ではない)。
- 数値と期限: 8-1 の測り方は、`cargo` の stoppedInBuildings(駅・港の敷地の中で止まったトラック)。今の値は全体で506、うち28755で492。目標は250以下。この案で目標まで届くかは見積もれない。期限は見回り2(20日目)。
- 確認方法: `vehicles_stuck`(kind=train) の byTarget で 40031 に向かう列車の数(今は0)。`cargo` の stoppedInBuildingsTop で 28755 の止まったトラック(今は492)と、stoppedInBuildings の合計(今は506)。見回り1と見回り2で、同じ道具・同じ条件で比べる。
- 不確かな点:
  - 列車の行き先の決め方が分からない。13893 など、動いていて接続もある駅にも列車が来ていない。動かすだけで列車が来るかは未確認。
  - 列車が来なければ、この案は効かない。維持費だけがかかる。
  - 効果の量は見積もれない。
- 試し:
  - 仮説: 40031 が動けば、貨物列車の行き先候補に入り、28755 に集まる積み荷の一部が40031へ回る。そうすれば28755 敷地内の待ちが減る。
  - 測る数: `vehicles_stuck`(kind=train) の byTarget にある 40031 の台数(基準は0台)と、`cargo` の stoppedInBuildings(基準は506。うち28755で492)。
  - 場所: 貨物駅40031(-1780, -1605)と、貨物駅28755(3449, -1555)。
  - 基準: 40031 向けの列車0台、28755 の敷地で止まったトラック492台、全体506台。
  - 判定: 20日目に40031 向けの列車が1台以上で、28755 の敷地の止まりが492より減れば効いたとみる。列車0なら止める。
  - 編成方針の「分からないこと」: 該当なし(列車の行き先の決め方は、この試しで確かめる)。

### 費用

- 建設費: 0(既存の建物を動かすだけ)
- 週の維持費の増え分: +1,440 / 週(`list_building_types` の Cargo Center の upkeepPerWeek。予算100%のとき)。

## 案2: 乗客がほぼいないバス路線を消し、バスの台数と維持費を減らす

### 施策

- 案の id: port-2
- 施策: 乗客が0〜21人しかないバス路線を8本消す。`remove_transport_line` を line 番号(list_transport_lines の line)で呼ぶ。対象は、直近の周期の乗客(passengersLastPeriod)が0〜16 の路線で、台数の合計が多いもの。
- 議決: 取り壊し

### 実行計画

- 実行可否: 確認済み
- 対象と操作順: 各路線を `remove_transport_line(line=<番号>)` で消す。順は下の通り。
  1. line=46(Bus Line 9。台数18、乗客0)
  2. line=107(Bus Line 5。台数15、乗客0)
  3. line=153(Bus Line 63。台数5、乗客0)
  4. line=187(Bus Line 64。台数5、乗客0)
  5. line=234(Bus Line 4。台数9、乗客0)
  6. line=203(Bus Line 81。台数15、乗客0、pathFailed 1)
  7. line=139(Bus Line 38。台数101、乗客5、路線長20.31km)
  8. line=21(Bus Line 39。台数65、乗客16、路線長12.82km)
  消す前に `list_transport_lines`(type=bus)で、passengersLastPeriod が上の値のままか再確認する。
- 設置条件の確認: 建物は置かない。路線を消す操作なので、道路・建物の敷地の確認は不要。`list_transport_lines` で 8本すべてが存在することを確認済み(name、number、line)。
- 接続工事: 不要
- 予備候補: なし。路線を消す操作は、確認した8本だけを対象にする。
- 中止する条件:
  - 実行の直前に、路線の passengersLastPeriod が上の値より増えていた路線は消さない(例: 乗客が30を超えた路線)。
  - `remove_transport_line` が断ったら、その路線だけ飛ばし、残りは続ける。

### 期待する効果

- 改善の見込み: 8本の路線は、台数が233台あるのに、直近の周期で乗客が0〜16人だった。走る車が道を塞ぎ、交通の流れを下げていると見る(予想)。消せば、6-3 の流れが改善する方向に動くと予想する。同時に、バスの維持費が減る。
- 数値と期限: 6-3 の測り方は、`traffic` の流れ(%)。今は51%、止まった車は1,008。目標は60%以上。流れの改善量は見積もれない。期限は見回り2(20日目)。維持費は `economy_breakdown` の PublicTransportBus の expenses で測る。今は22,051 / 週。
- 確認方法:
  - `traffic`(街全体。x、z、radius を省く)の flow と blocked を、見回り1・見回り2・月末で比べる。今は flow 51%、blocked 1,008。
  - `list_transport_lines`(type=bus)で、路線の台数の合計を比べる。今は約1,930台。
  - `economy_breakdown` の PublicTransportBus の expenses を比べる。今は22,051。
- 不確かな点:
  - 流れが上がるかは見積もれない。バスは全体の約2割(約1,930台 / 車と合わせて約9,500台)で、消す8本はそのうち233台。
  - 乗客0〜21の路線が消えると、その沿線の公共交通の届き方は減る(路線の届き具合は未確認)。
  - 維持費の減りは台数から見積もる。1台あたり約11.4 / 週(22,051 ÷ 約1,930台)、消す233台で約2,700 / 週の減り(概算)。
- 試し:
  - 仮説: 乗客がほとんどいないのに多くのバスが走っていて、それが道を塞いでいる。消せば、6-3 の流れが上がる。
  - 測る数: 6-3 の測り方の `traffic` の flow と blocked(担当の数字)。あわせて、路線の台数と PublicTransportBus の expenses(担当の範囲の数字)。
  - 場所: 街全体の8路線(路線番号 4、5、9、38、39、63、64、81)。
  - 基準: flow 51%、blocked 1,008、路線の台数約1,930、PublicTransportBus の expenses 22,051 / 週。
  - 判定: 20日目に flow が51%より上がれば効いたとみる。上がらなければ、残りの路線を見直す。
  - 編成方針の「分からないこと」: 該当なし(この案は局の判断による試し)。

### 費用

- 建設費: 0
- 週の維持費の増え分: 約 −2,700 / 週(減る)。233台 × 約11.4 / 週 の概算。`economy_breakdown` で、消した後に確かめる。

### 戻せるか

戻せない。路線を消すと、停留所の並びと台数の記録は元に戻らない。路線は `create_transport_line` で作り直せるが、同じ形にはならない。

## 判断の根拠

- 8-1: 止まったトラック506のうち492は、貨物駅28755 の敷地の中で「空き待ち」になっている。駅の外の道は詰まっていない(radius 300 の traffic で blocked 0)。このため、道を広げても効きにくい。列車11本が全部28755 に入るので、西の駅40031(電気・水・下水・外との線路が届く。TurnedOff)を動かす案1を試しとして出す。列車の行き先は未確認なので、20日目に列車が来なければ止める。
- 6-3: バスの台数は約1,930台で、車の7,557台と合わせた約9,500台の約2割を占める。乗客0〜21の8路線に233台が集中している。消せば交通を減らせる。維持費も約2,700/週減る見込み。消す操作は取り壊しの議決が要るため、案2として出す。効き目の量は見積もれない。
- 案の数を2件にした理由: 5-1、5-2 の観光は担当外で、空港は週4,800の維持費が増え分の上限4,000を超えるため出せない。8-1 と 6-3 の手は、今月の数字で効く見込みがあるものに絞った。3件目は根拠が足りない。
- 財政: 案1は+1,440/週、案2は約−2,700/週。合わせて週の収支を悪くしない。
