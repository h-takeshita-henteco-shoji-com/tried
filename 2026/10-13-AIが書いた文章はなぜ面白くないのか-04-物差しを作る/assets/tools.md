# 使う道具の一覧

`measures.md` の4つの手順で使う道具。
導入と試しの計測は翌日に行う。ここでは、何を何に使うかだけを決める。
Hugging Face のモデルは、2026-10-13 に Hub で実在とライセンスを確かめた。

## AI

- **Claude Haiku 4.5**(`claude-haiku-4-5-20251001`): AIの読者。冒頭で予想し、全文で答え合わせをする
- **Claude Opus 5.5**: 未読の原文の要約と、文の役割を見分ける担当。#47 と同じ担当にそろえる
- **Claude Sonnet 5.5**: 要約から書き直しを作る。#47 と同じ指示文を使う

AIの読者は、10回とも新しい会話で呼ぶ。呼び方(API か Claude Code の `claude -p` か)は導入の日に決める。`claude -p` を使う場合は、リポジトリの外の空のフォルダから呼ぶ。このリポジトリの `CLAUDE.md` を読ませないためである。

## サプライザルを測る言語モデル

3つ使う。作った組織と学習データが違うモデルを選んだ。1つのモデルの癖で結論を出さないためである。

- **llm-jp/llm-jp-3-1.8b**: 18.7億パラメータ。Apache-2.0。国立情報学研究所の LLM-jp が作った
- **sbintuitions/sarashina2.2-1b**: 14.1億パラメータ。MIT。SB Intuitions が作った
- **rinna/japanese-gpt2-medium**: 3.6億パラメータ。MIT。CC-100 と Wikipedia で学習した。古く小さいモデルを混ぜ、性能の差で結果が変わるかを見る
  - 一度に読める長さが1,024トークンと短い。長い文章では、直前の文脈だけを与えて測る

予備: **tokyotech-llm/Llama-3.1-Swallow-8B-v0.2**(80億パラメータ、Llama 3.1 のライセンス)。3つの結果が割れたときに足す。Mac で動かすには重いので、最初は使わない。

どれも指示調整前のモデル(base モデル)である。指示調整したモデルは、確率の分布が平らでなくなるためである。

## 埋め込みモデル

- **cl-nagoya/ruri-v3-310m**: 日本語の文の埋め込み。Apache-2.0。AIの読者の「外れの大きさ」と「予想の散らばり」に使う
  - 用途ごとに入力の頭に付ける語(プレフィックス)が決まっている。文どうしの意味の近さに使う語を、導入の日に model card で確かめる

## Python のライブラリ

- **transformers、torch**: 言語モデルと埋め込みを動かす。Mac の GPU(MPS)で動かす
- **sentence-transformers**: 埋め込みを出す
- **krippendorff**: 文の役割を見分けた結果の一致率(Krippendorff の α)を出す
- **scipy**: モデルどうしの順位相関(Spearman)を出す
- **matplotlib**: アーク図と、開いている辺の数・跳ね比・サプライザルの推移を描く
- **fugashi、unidic-lite**: 形態素解析(文を単語に分けて品詞を付ける処理)。今回の手順では使わない。条件7の固有名詞と数字を数える日に使う

## 自分で書くスクリプト

`code/` の下に置く。

- **文と段落に番号を振る**: 区切りの決まりは `measures.md` の「文と段落に番号を振る」
- **冒頭だけを表示する**: 本文の20%を超えた最初の段落の終わりまで出す。続きを画面に出さない
- **1段落ずつ表示する**: 冒頭の後を、キーを押すたびに1段落ずつ出す。先の段落を画面に出さない
- **伏せた組を作る**: 原文と書き直しに無作為の記号を振り、対応表を `key.md` に分ける
- **サプライザルを出す**: 3つのモデルで、文ごとの1文字あたりの値を出す
- **数える**: 文の長さ、位置(%)、見分けた文の役割と関連から出す位置と文数
- **グラフの指標を出す**: `relations.tsv` から、辺の長さ、開いている辺の数、辺の向き、交差と入れ子を数え、アーク図を描く
- **全う度合いを出す**: 役割の文に、自分の読みとAIの読者の反応を重ねる
- **突き合わせる**: 4つの方法の結果を、組ごとに1つの表にまとめる
