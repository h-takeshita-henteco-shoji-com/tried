### m03-2 南西に埋立地を1棟置く(試し)

- 元にした局の案: health。手直しした点: なし
- 議決: 要らない
- 採択理由: ごみの印は15→33→40と増え、いちばん多い場所 -2213,-2029 の近くの埋立地5つと焼却場41481 は満杯か98%である。受け入れの空いた埋立地を足すと収集車が出るかを確かめ、4-4 の原因を絞る手と判断した。
- 今月選んだ理由: 重点3(4-4)に当たり、分からないことの一覧の「ごみの印が増え続ける原因」に直接当たる試しである。建設費4,000・週160と安く、置き場所の道路・重なり・高さを局が確かめている。
- 公約: 直接はなし(暮らしの基盤と健康の採点、幸福度のため)
- 市の計画: 4-4 資源循環
- 操作:
  1. 実行前に `buildings_near(x=-1920, z=-2075, radius=70, brief=true)` を測る。Garbage 以外の建物が敷地内(x -1952〜-1888、z -2115〜-2035)にあれば中止
  2. 実行前に `buildings_near(x=-2213, z=-2029, radius=450, problem="Garbage", brief=true)` の total と、`complaints` の Garbage を基準として記録する(市長の今月の値は13)
  3. `place_building(prefab="Landfill Site", x=-1920, z=-2075, facing="west", pay=true)`。entrance.road が null なら中止
  4. 第1候補が reasons つきで断られたときだけ、予備 `place_building(prefab="Landfill Site", x=-1920, z=-2165, facing="west", pay=true)`
  5. 実行後に `buildings_near(x=-1920, z=-2075, radius=30, service="Garbage")` で新しい埋立地の id と storage を記録する(予備なら x=-1920, z=-2165)
- 実行計画: 局の確認は、`zones_at`(-1920,-2075、r50)Unzoned 41 全部空き、`buildings_near`(r70)は4801(-1984,-2050)と31004(-1976,-2095)のみで敷地の外、`height_at` 57.2〜58.6 で平らで水なし、`net_near` で x=-1960 の Basic Road(区間23887、36432)が敷地の西8mを通り入口が面する、`list_building_types` で 10×8マス・電気水下水は要らない・道路が要る。局が未確認とした土地の買い済みは、市長が `city_info` の ownedTiles 81(9×9 の全区画を持つ)で確かめた。予備 (-1920,-2165) は `zones_at`(r45)Unzoned 37 全部空き、`buildings_near`(r65)は9347 のみで敷地の外、`height_at` 53.6、道は x=-1960 の区間16384・17190。中止する条件: 敷地内に建物が出た、entrance.road が null、予備も断られた、所持金が建設費より少ない
- 費用: 建設費 4,000、週の維持費の増え分 160(ごみの予算150%で最大約240)
- 予想: 局の見込みは、月末(2050-04-01)までに南西の印の範囲の Garbage が半分以下、街全体のごみの印 40→30以下。数値は見積もれない(収集車が近くの印へ向かうかは未確認)。確認は、`complaints` の Garbage の buildings と hotspot、`buildings_near(x=-2213, z=-2029, radius=450, problem="Garbage", brief=true)` の total(実行前の基準と比べる)、新しい埋立地の storage と収集車の使用数。不確かな点: 収集車が近い施設から出るとは限らない。8,000,000 は街の使用量の約6%で、足りるかは分からない
- 試し: 仮説「満ちた施設ばかりの南西に、空きのある埋立地を足せば、収集車が出てごみの印が減る」。測る数は `buildings_near(x=-2213, z=-2029, radius=450, problem="Garbage", brief=true)` の total(街全体の数でなく、この範囲に絞る。基準は実行前に測る。今月の市長の値は13)と、新しい埋立地の storage。場所は -1920,-2075。分からないことの一覧の「ごみの印が増え続ける原因(焼却場の満ち具合か、収集車が届かないのか)」に当たる。storage が増えて印が減れば受け入れ先の不足、storage が増えないなら収集車が届かない側と読む

- 戻せるか: 戻せる(`set_building_active` で止められる。建設費は戻らない)

- 議決: 予算

- 公約: 3
- 市の計画: 8-1 物流・人流のゲートウェイ(財政の守る線: 週の収支を黒字に保つ)

  2. `economy_breakdown` で PublicTransportTrain の支出が12,000〜13,500 であることを確かめる

  4. `economy` で train が昼100・夜100 になったことを確かめる
- 実行計画: 建設ではない。対象は train の予算、変更値は昼夜とも120→100(-20ポイント、要領の±20の枠内)。局は今月 `economy` で昼夜120、`economy_breakdown` で PublicTransportTrain 12,701 を確かめた。予備候補なし。中止する条件: train が昼夜とも120でない、または PublicTransportTrain の支出が12,000未満か13,500超
- 費用: 建設費 0、週の維持費の増え分 約-1,700(減る側)
- 予想: PublicTransportTrain の支出 12,701→約11,000〜11,500、週の収支 +8,035→+9,500前後。期限は翌月の月例(2050-04-01)。確認は `economy_breakdown` の PublicTransportTrain と `city_info` の週の収支。参考に `cargo` の stoppedInBuildings(555、28755 は534)と `vehicles_stuck(kind="truck", building=28755, limit=10)` の 7days+(485)も見るが、m03-1 が混ざるので効きの判定には使わない。不確かな点: 支出が1,728分ぴったり戻るかは分からない
