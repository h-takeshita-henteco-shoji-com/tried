## 施策

### m02-1 貨物駅28755 の出口の東西路を Small 4 Lane Road に差し替える(試し)

- 元にした局の案: port。手直しした点: なし
- 議決: 要らない
- 採択理由: 貨物駅28755 の敷地の中の止まったトラックは550で、8-1 の目標250から最も遠い。出口の東西路の Basic Road 2区間は密度100と80で、市長の `traffic(3240,-1340,150)` でも同じ値だった。この区間の流れを広げ、道の上の滞留と駅の詰まりの原因を絞る。
- 今月選んだ理由: 今月の重点 8-1 と 6-3 に当たり、分からないことの1項目目(貨物駅の詰まり)の原因を絞る試しを兼ねる。建設費は約750と小さく、維持費は増えない。
- 公約: 直接なし。品物の流れが戻れば、働き口(6-4、7-1)を通じて公約1の住宅の需要につながる見込み。公約3の線の中で
- 市の計画: 8-1 物流・人流のゲートウェイ(6-3 公共交通を主軸とした交通体系にも)
- 操作:
  1. `upgrade_road(prefab="Small 4 Lane Road", points=[[3320,-1340],[3240,-1340],[3160,-1340]], tolerance=8, pay=True, demolish=False)`
  2. 戻り値の upgraded が 2 であることを確かめる
- 実行計画:
  - 設置条件: 局の `test_upgrade_road` で matched 2、upgraded 2、skipped なし、demolishedBuildings なし。市長も同じ引数で試し、同じ結果(cost 0、zonesKept true)だった。同じ幅の差し替えで沿道の建物は壊れない
  - 接続工事: 不要
  - 予備候補: なし。(3495,-1490)〜(3400,-1340) は SlopeTooSteep・TooShort・ObjectCollision で断られたため含めない
  - 中止する条件: 実行時に upgraded が 2 未満、または demolishedBuildings が1以上なら見送る
- 費用: 建設費 約750(査定の見積もり。試す道具の表示は 0)、週の維持費の増え分 約0(Basic Road と同じ 40/km)
- 予想:
  - 改善の見込み: 西行きの車線が増え、道の上で止まる車が減る。敷地の中の550台そのものを直すとは確かめられていない
  - 今の値と予想値・期限: segment 31488 の密度 100、27961 の密度 80 → 60以下。街全体の流れ 52% → 53%以上。`cargo` の stoppedOnRoads 364 → 減る。期限は月末(30日目)。敷地の中の550台は変わらない見込み
  - 確認方法: `traffic(x=3240, z=-1340, radius=150)` の busiest で segment 31488・27961 の密度、`cargo` の stoppedOnRoads と stoppedInBuildings
  - 不確かな点: 東隣の segment 11279 はすでに Small 4 Lane Road で密度100。詰まりが下流の合流で決まるなら、差し替えだけでは効かない。数値は見積もれない
- 試し: 仮説「z=-1340 の西行きを4車線にすると、貨物駅からの荷物の車の道の上の滞留が減り、`traffic` の流れが上がる」。測る数は segment 31488・27961 の密度と `cargo` の stoppedOnRoads。場所は (3160〜3320,-1340)。基準は 100・80・364(市長の実行前の確かめで 100・80 を再確認)。分からないことの一覧の「貨物駅28755 の敷地の中で、なぜトラックが止まっているか」を絞る材料にする
- ほかの局への響き: 道路が広がると、近くの車がこの道へ寄り、周りの交差点(6-3)が混む恐れがある。費用は小さく、財政(公約3)への響きはほぼない。品物の流れ(economy の品物がない店)は、良くなる方向の見込みだが確かめられない
- 戻せるか: 戻せる。`upgrade_road` で Basic Road に差し替え直す
- 取り壊しのとき: 該当なし

### m02-2 交差点 (2110,330) に信号を付ける(試し)

- 元にした局の案: roads。手直しした点: なし
- 議決: 要らない
- 採択理由: (2101,302) の半径150m は blocked 92、congestion 71、密度80で、街で止まった車が最も多い場所の1つ。T字の node 30603 には信号も譲れもない。前月の同じ型の手 (2236,-950) は blocked を 84 → 45 に減らした。
- 今月選んだ理由: 今月の重点 6-3 に当たり、前月に効いた手を、調査 s01-3 が原因と見た交差点に広げる。建設費0で戻せる。
- 公約: 直接なし。市の計画 6-3
- 市の計画: 6-3 公共交通を主軸とした交通体系
- 操作:
  1. 実行前に `junction_info(2110,330)` で trafficLights false、canEnableLights true を確かめる
  2. `set_traffic_lights(x=2110, z=330, active=True)`
  3. `junction_info(2110,330)` で trafficLights が true か確かめる
- 実行計画:
  - 設置条件: 局の `junction_info` で node 30603、T字(segment 3990 / 22887 / 26735、すべて Small 4 Lane Road)、trafficLights false、canEnableLights true。市長の `junction_info(2110,330)` でも同じだった
  - 接続工事: 不要
  - 予備候補: なし。(2882,-945) は40m以内に交差点がない
  - 中止する条件: 実行前の `junction_info` で canEnableLights が false、またはすでに信号がある場合は見送る
- 費用: 建設費 0、週の維持費の増え分 未確認(道具で確かめられない。前月の信号でも目立った増えはなかった)
- 予想:
  - 改善の見込み: 交差点の流れが整理され、止まった車が減る
  - 今の値と予想値・期限: `traffic(x=2101, z=302, radius=150)` の blocked 92 → 約45(半減が目安)。blockedSpots (2101,302) は 55。期限は20日後(見回り2)と月末
  - 確認方法: 同じ `traffic(x=2101, z=302, radius=150)` の blocked と blockedSpots、街全体の flow(今52%)
  - 不確かな点: 北の (2152,443) の segment 6523 も密度100で、混雑が交差点の外から来ているなら効かない。信号の待ちで逆に混むこともある
- 試し: 仮説「信号で交差点の流れが整理され、止まった車が減る」。測る数は `traffic(x=2101, z=302, radius=150)` の blocked。場所は (2110,330)。基準は blocked 92、最多地点 55(市長の確かめで同じ値)。分からないことの一覧には当たらない。6-3 の前月の試しの続き
- ほかの局への響き: 死体の印の hotspot (2190,27) から約320m北で、火葬場 (2224,60) の霊柩車の道筋に当たるかもしれない。流れが良くなれば霊柩車の遅れ(1-2)は減るが、信号の待ちで悪くなる恐れもある。消防車・品物の車の通り道でも同じ。財政への響きはない
- 戻せるか: 戻せる。`set_traffic_lights(x=2110, z=330, active=False)`
- 取り壊しのとき: 該当なし

### m02-3 高密度住宅街の空き地2か所に駐車場の飾りを置く(試し)

- 元にした局の案: urban。手直しした点: なし
- 議決: 要らない
- 採択理由: 公園など(Beautification)は81で、4-2 の目標100に19足りない。区画の指定のない空き地2か所に、壊す建物なしで置けることを局と市長の `test_place_building` で確かめた。電気は局の `map_layer` で25点すべて1。
- 今月選んだ理由: 重点の外だが、建設費2,000・週32と小さく、ほかの2件と場所が重ならない。前月に採らなかった理由(電気の未確認)に局が手当てをして出し直した。
- 公約: 直接なし。地価が上がれば住宅のレベルが上がり、公約1の家の数につながる見込み
- 市の計画: 4-2 花や緑による潤い(4-1 都市と自然が調和したコンパクトなまちの地価にも)
- 操作:
  1. `place_building(prefab="Decoration Concrete Parking Lot 01", x=2135, z=-365, facing="west")`
  2. `place_building(prefab="Decoration Concrete Parking Lot 01", x=2135, z=-322, facing="west")`
- 実行計画:
  - 設置条件: (2135,-365) は ok、取り壊し0、入口 (2119,-365) が segment 32172(Basic Road)に距離1。(2135,-322) は ok、取り壊し0、入口 (2119,-322) が segment 13569(Basic Road)に距離1。市長も同じ引数で試し、同じ結果(angleUsed 90、cost 1,000、needs は電気のみ)だった
  - 電気: 局の `map_layer`(electricity_service、中心 (2135,-365)、半径100、n=5)で25点すべて1。水・下水は要らない
  - 敷地: 局の `zone_map`(中心 (2200,-380)、半径150)で、2か所とも区画の指定がない空き地
  - 接続工事: 不要
  - 予備候補: なし。(2135,-408) は建物44025 を壊すため使わない
  - 中止する条件: 実行前の `test_place_building` が断る、または wouldDemolish が0でないなら、その1棟を見送る
- 費用: 建設費 2,000(1,000 × 2)、週の維持費の増え分 32(16 × 2)
- 予想:
  - 改善の見込み: 4-2 の数を2棟増やす。地価への効きは小さいと見る
  - 今の値と予想値・期限: `buildings_near`(service=Beautification、全街)81 → 83。期限は月末。地価は見積もれない
  - 確認方法: `buildings_near`(service=Beautification)の total、`land_value(x=2135, z=-345, radius=100)` の average
  - 不確かな点: 駐車場の飾りが公園と同じに地価を上げるかは確かめられていない。目標100までは、この案だけでは届かない
- 試し: 仮説「Beautification の建物を街区の空きに置くと、周辺の地価が上がる」。測る数は `land_value(x=2135, z=-345, radius=100)` の average と Beautification の数。場所は (2135,-322) と (2135,-365)。基準は Beautification 81、地価の average 62(市長が今月測った。min 43、max 73)。分からないことの一覧には当たらない
- ほかの局への響き: 維持費が週32増え、財政(公約3)は +6,569 から少し減る。電気の使用は増えるが、容量 2,389,600 に対し使用 1,707,280 で余裕がある。交通・健康・教育への響きは見込まない
- 戻せるか: 戻せる。`bulldoze` で取り除ける(建設費の払い戻しはない)
- 取り壊しのとき: 該当なし

## 判断の根拠

施策の案を出した3局は、どれも試す道具の結果を書いており、市長が同じ引数で試しても同じ結果だった。3件の建設費は合わせて約2,750、維持費の増え分は約32で、上限 1,053,771 と枠 5,000 に大きく収まる。重点の 8-1 と 6-3 に当たる m02-1、m02-2 を中心にし、m02-1 は分からないことの1項目目を絞る試しを兼ねる。試しの場所は (3160〜3320,-1340)、(2110,330)、(2135,-345) で互いに600m以上離れ、重ならない。調査は分からないことの3項目に当たる port、health、fire を採った。
