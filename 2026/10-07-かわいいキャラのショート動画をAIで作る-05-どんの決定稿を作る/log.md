## 試したこと

ぬめの決定稿を参照画像にして、同じ画風でカピバラの「どん」の決定稿を作る。
湯に浸かり首から上だけを出した姿を正面と斜めで出し、目を半分閉じた表情を基本にする。
ぬめと同じ画面に置いたときの大きさの比率(どんの顔の高さ = ぬめの体長の約6倍)も1枚で確かめる。
成果物はどんの決定稿、2匹を並べた比率確認の画像、使った指示文。

### 性格を絵に出す(指示文 1d を作成)

- 見た印象は「性格が絵に表現されていない」。プロフィールと照らすと、ずれは3つあった。

  - 線1本の目は「寝ている」に読める。どんは「察する」ので、見ている目が要る。
  - 肩まで出したため、「首から上だけ出して見守る」記号が消えた。
- 性格を形の言葉に置き換えた。動じない→あごまで湯、頭はまっすぐ。察するが言わない→まぶた半分と黒目の上半分、閉じた口。おおらか→手ぬぐいが少し斜め。年長→下ぶくれの広い顔。見守る→顔は正面、目だけ左へ。
- 向きは「顔は正面、目だけ横」にした(案A)。三面図の基準にできるため。斜めの 1b を決定稿にする案Bは採らない。

### 決定稿を全身に変える(指示文 1e を作成)

- 本人の指摘: 「今は湯に浸かった絵ではなく、全身を描くべきでは」。
- 採った。湯に浸かった姿は画面での使い方で、キャラの設計図ではない。ぬめの決定稿も、全身を正面から描いた無地の背景の1枚だった。
- 全身を先に決める理由は2つ。
  - 湯の中の体を決めずに首から上だけ固めると、斜めや横の絵で、AIが毎回違う体を足す。
  - 湯に沈む表現がモデレーションで止まる問題を避けられる。
- 世界観の決まりごと「どんの体を水の上に出さない」は、画面の決まりとして残す。決定稿と三面図には全身を描く。
- Issue の「湯に浸かった首から上を正面と斜めで」は、全身の決定稿から作る次の段に回す。
- 1d は送らず、1e に置き換えた。

### 比率確認(指示文 2 を作成)

- 上限60分を超えるが、本人の判断で続ける。
- 決定稿を全身にしたので、比率確認も全身どうしで並べる。湯は描かない。
- 比率は「どんの頭の高さ(耳と手ぬぐいを除く)= ぬめの体の幅(触角を除く)の6倍」と書いた。生成後に画素数を測って確かめる。

### 比率確認の結果(指示文 2 と、画素数での合成)

AIの結果: `assets/generated/nanobananapro_5.png`。

- 2匹とも画風を保ったまま、1枚に並んだ。どんは体を少しぬめの側へ向けた。
- 比率は守られなかった。どんの頭の高さ約360px、ぬめの体の幅約210〜250px。約1.5〜1.7倍で、指示の6倍に遠い。
- 16:9 の指示も効かず、正方形になった。

画素数で合成した結果: `assets/generated/ratio-composite.png`(Claude Code が Python で作成)。

- 決定稿どうしを、どんの頭の高さ(約290px)= ぬめの幅の6倍になるよう縮めて並べた。ぬめは約50px。
- 6倍だと、ぬめは足元の小さな点になる。表情も露も読めない。縮めたことで、ぬめの輪郭も細くなった。
- AIは「6倍」を守らず、2匹とも見える大きさに寄せた。設定の比率と、画面で読める大きさが食い違っている。

### 比率を3倍に変える

- 案は3つ出した。A: 6倍を守り、手前と奥の遠近で差を縮める。B: 3倍程度に縮める。C: 判断を絵コンテの日に回す。
- 本人は B を選んだ。実物らしさより、スマホでぬめの表情が読めることを取る。
- 3倍で合成した: `assets/generated/ratio-composite-3x.png`。ぬめは約100px。足元にいても、触角と露が読める。
- 10-06 の世界観設定書とプロフィールの「6倍」「6分の1」は、公開済フォルダなので直さない。ここに差し戻しとして残す。
  - 世界観設定書: 「どんの顔の高さが、ぬめの体長の約6倍」→ 約3倍。
  - プロフィール: ぬめ「どんの顔の高さの6分の1」→ 3分の1。

## 学び

- 画風は参照画像1枚で別の動物に移った。1枚目から太い黒線と平塗りが揃った。
- 性格は移らなかった。気持ちの言葉(Cheerful)は口を笑わせ、目の形を細かく書くとじと目になった。性格は形の言葉で書くが、線を足さない形を選ぶ。
- 画風の芯は線の少なさだった。どんの目を上が平らな半円にしたとき、ぬめと同じ世界に並んだ。
- 直しは「〜にする」より「〜を消す」。4つ並べて1つしか効かなかった指示が、名指しで消すと5つとも効いた。
- 決定稿は全身で作る。湯に浸かった姿は画面の見せ方で、設計図ではない。Issue の一文をそのまま絵にしようとして、遠回りした。
- 設定の比率は絵にして確かめる。6倍はぬめが点になる比率だった。3倍に変えた。
- モデレーションで止まったら、文面を1行まで削って切り分ける。それでも止まれば窓口を替える。同じ指示文でも Nano Banana Pro のサービスでは止まり、Gemini では通った。
- 2枚添付して役割を書き分けても、Gemini は土台を取り違えた。直しは1枚だけ添付する。
- AIに3回頼んで直らない小さな線は、Python で塗り直す方が早い。平塗りの画風なら継ぎ目が出ない。
