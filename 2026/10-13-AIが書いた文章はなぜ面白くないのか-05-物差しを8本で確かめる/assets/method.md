# 数値化の処理フローと計算式

今日の数値は2系統で出した。スクリプトは `code/yardstick/` にある。判定の決め方は、測る前に `criteria.md` に固定した。

- **数える**(1〜6): 文の長さとサプライザル。AIの判断は入らない
- **A〜D の練習**(7〜11): 文の役割、AIの読者、覚えていないかの確認、τ の候補。AIの判断が入る

## 処理フロー

```
本文をそろえる(prepare.py → texts/*.txt)
  ↓
文と段落に番号を振る(segment.py)
  ↓            ↓
文の長さを数える   サプライザルを出す(surprisal.py → surprisal.tsv)
(count.py)        ↓
  ↓            文書ごとの指標にまとめる(count.py)
  ↓            ↓
  └──→ 判断を再現したかを判定する(count.py → results.md)
```

再現するときのコマンド:

```bash
T=2026/10-13-AIが書いた文章はなぜ面白くないのか-05-物差しを8本で確かめる/assets
python code/yardstick/prepare.py 2026 $T/texts
python code/yardstick/surprisal.py $T/texts $T/surprisal.tsv
python code/yardstick/count.py $T/texts $T/surprisal.tsv > $T/results.md
```

## 1. 本文をそろえる(prepare.py)

**なぜ要るか。** 8本の形式(Markdown、HTML、Wiki記法)がばらばらで、そのままでは同じ数え方ができない。

- 1行目を題、空行のあとを本文とするテキストにした
- 原文の入手元
  - A: Wikisource の Wiki記法(`action=raw`)から、本文の段落だけを取った
  - B: 青空文庫の HTML から本文を取り、ルビ(読み仮名)と全角空白を除いた。末尾の「(昭和八年十月、鉄塔)」は除いた
  - C: 気象庁の HTML から本文を取った。表の各行は「種類:特徴」の1段落にした
  - D: 10-08 の `article.md` から取った
- 書き直しは、#47 の `rewrites/` から取った
- Markdown は次のように直した
  - 最初の `# ` 行(C は太字の行)を題にした
  - 見出しの記号、箇条書きの記号、太字、コードの記号を除いた。見出しと箇条書きの文は残した
  - 表の行は、セルを「:」でつなぎ、「。」で閉じた1文にした
  - 画像、コードブロック、区切り線を除いた。リンクは文字だけ残した

この段は、最初はその場で書いたスクリプトで流した。後から同じ処理を `prepare.py` に残し、8本とも1文字も違わずに作り直せることを確かめた。

## 2. 文と段落に番号を振る(segment.py)

**なぜ要るか。** 文の長さもサプライザルも、文を単位に数えるため。区切りは `measures.md` の決まりに従った。

- 段落は空行で区切る
- 文は「。」「!」「?」と改行で区切る。かぎかっこと丸かっこの中では区切らない
- 閉じかっこだけが残った断片は、前の文に付ける
- 文の長さ ℓᵢ は、空白と改行を除いた文字数
- 本文の総文字数 L = Σℓᵢ。題は含めない

## 3. 文の長さを数える(count.py)

**なぜ要るか。** 1文の書きぶり(読みやすさ)と緩急(面白さの候補)を、AIの判断なしで出すため。

文の数を n とする。

- **文の長さの平均** m = Σℓᵢ ÷ n
- **文の長さの標準偏差** σ = √( Σ(ℓᵢ − m)² ÷ n )。母標準偏差である
- **文の長さの変動係数** CV = σ ÷ m。文章の長さに左右されない緩急の大きさ
- **隣の文との長さの差** D = Σ|ℓᵢ₊₁ − ℓᵢ| ÷ (n − 1)。段落をまたぐ隣どうしも数える
- **漢字の割合** K = 本文の漢字の数 ÷ 本文の文字数(空白と改行を除く)。漢字は Unicode の `一`〜`鿿` と「々〆ヶ」とした

## 4. サプライザルを出す(surprisal.py)

**なぜ要るか。** 各文が言語モデルにとってどれだけ予想外かを、人の判断なしで数えるため。

### 使ったモデル

| 記号 | モデル | 一度に読む長さ |
|---|---|---|
| llmjp | llm-jp/llm-jp-3-1.8b | 2,048トークン(上限4,096を2,048で頭打ち) |
| sarashina | sbintuitions/sarashina2.2-1b | 2,048トークン(上限8,192を2,048で頭打ち) |
| rinna | rinna/japanese-gpt2-medium | 1,024トークン |

- 重みは float32 で読み、CPU で動かした。Mac の GPU(MPS)では、転送と計算が止まったためである
- 8本×3モデルで約6分かかった

### 手順

1. 文章を1つの文字列にする。題、改行、本文の順に並べる。同じ段落の文は区切りなしでつなぎ、段落の間に改行を1つ入れる。各文が文字列のどこからどこまでかを記録する
2. 特殊トークンを付けずにトークンに分け、先頭に BOS トークンを1つ足す。各トークンの開始位置(文字列の何文字目か)を取る
3. 各トークン wₜ のサプライザルを出す
   - sₜ = −log₂ p(wₜ | w₀ … wₜ₋₁)
   - 単位はビットである
4. 一度に読める長さ N を超える文章は、窓をずらして測る
   - 最初の窓は先頭から N トークン。窓の中のトークンをすべて測る
   - 次の窓は、前の窓の終わりから N/2 戻った位置から始める。前の窓で測っていないトークンだけを測る
   - したがって2つ目以降の窓では、各トークンに少なくとも N/2 トークンの文脈がある
   - 今回は、rinna で B の原文(1,919トークン)、B の書き直し(1,450)、D の原文(1,575)、D の書き直し(1,205)が窓をずらす対象になった。ほかは1つの窓に収まった
5. トークンを文に割り当てる。トークンの開始位置が文の範囲に入れば、その文のトークンとする。題と改行のトークンは、どの文にも入れない
6. 文ごとの値を出す
   - **1文字あたりのサプライザル** uᵢ = Σ(文 i のトークンの sₜ) ÷ ℓᵢ
   - 文字数で割るのは、モデルごとにトークンの切り方が違うためである

出力は `surprisal.tsv`(モデル、文書、文番号、段落番号、文の長さ、uᵢ)である。

## 5. 文書ごとの指標にまとめる(count.py)

**なぜ要るか。** 文ごとの値を、文書どうしで比べられる1つの数にするため。モデルごとに別々に出す。

- **サプライザルの平均** ū = Σuᵢ ÷ n。文の長さで重みは付けていない
- **サプライザルの標準偏差** σᵤ = √( Σ(uᵢ − ū)² ÷ n )。起伏の大きさ
- **サプライザルの段落頭の差** Δ = (段落の最初の文の uᵢ の平均) − (それ以外の文の uᵢ の平均)
  - 1文だけの段落は、その文を段落の最初の文に数える
- **モデルどうしの順位相関**: 文書ごとに、2つのモデルの uᵢ の列で Spearman の ρ を出す(`scipy.stats.spearmanr`)。3組を出す
  - 手順書の決まりで、0.5未満の組がある文書は、サプライザルを結論に使わない

## 6. 判断を再現したかを判定する(count.py)

**なぜ要るか。** 指標が #47 の判断と同じ向きを出したかを、決まった式で決めるため。決め方は `criteria.md` に測る前に固定した。

各指標の値を x とし、向きを g とする。g は「大きいほど面白い(読みやすい)」なら +1、「小さいほど」なら −1 である。

| 軸 | 指標 | g |
|---|---|---|
| 面白さ | サプライザルの標準偏差、段落頭の差 | +1 |
| 面白さ | 文の長さの変動係数、隣の文との長さの差 | +1 |
| 読みやすさ | 文の長さの平均、漢字の割合、サプライザルの平均 | −1 |

### 面白さ

- **組の向き**: A、B、D の各組で、g × (x原文 − x書き直し) > 0 なら当たり。3組すべて当たれば「再現」
- **C の位置**: 8本を g × x の大きい順に並べる。C の原文と書き直しが、ともに5〜8位なら当たり

### 読みやすさ

- **組の向き**: A〜D の各組で、次のどちらかなら当たり。4組すべて当たれば「再現」
  - 同じとみなす: |x原文 − x書き直し| ≤ 0.05 × (|x原文| + |x書き直し|) ÷ 2
  - 書き直しが読みやすい側: g × (x書き直し − x原文) > 0

### 偶然で当たる確率

- 面白さの組の向きは、向きが五分五分なら3組すべて当たる確率が (1/2)³ = 1/8
- 面白さの指標は8個(文の長さ2、サプライザル2×3モデル)なので、偶然でも 8 × 1/8 = 1個は当たる見込みである
- 読みやすさの4組すべてが当たる確率は (1/2)⁴ = 1/16(「同じ」の幅を除く)。指標は5個なので、偶然の当たりは約0.3個である

## 8. 文の役割を見分ける(label.py、agreement.py)

**なぜ要るか。** 全う度合いは、どの文が転や問いかを決めてから測るため。

### 見分け方

- 指示文は `code/yardstick/prompts/label.md`。`measures.md` の3つの一覧と、`conditions.md` の定義を渡した。A〜D の実例は除いた
- 文章は「t00 題」「[p01]」「s001 本文」の形で、番号を付けて渡した
- 答えは roles、relations、features の3つの表で返させた
- 同じ指示で2回、別の会話で見分けさせた。1回目を本番にした

### 一致率

2つの結果を、結果1、結果2とする。

- **役割ごとの α**: 8本の全文を並べる。文ごとに「その役割が付いているか」を0か1にする。結果1と結果2の列で、Krippendorff の α(nominal)を出す。「読んでいる時点」と「読み終えた後」で別に出す
  - 役割の名前は、[全体] などの括弧を除いてそろえた
- **前後1文の版**: 結果1が1の文 i で、結果2が0なら、結果2の i−1 か i+1 の1を i に移してから α を出す
- **関連の一致率**: 関連 e = (種類, 始点, 終点) とする。範囲の終点は始まりの文を使う
  - 一致率 = ( 結果1の関連のうち結果2にもある割合 + 結果2の関連のうち結果1にもある割合 ) ÷ 2
  - 前後1文の版は、始点と終点がそれぞれ1文以内のずれなら同じとみなす

## 9. AIの読者(reader.py)

**なぜ要るか。** 読者の予想がどこで外れたかを、転の文の近くで取るため。

### 1回の読み方

1回につき1つの会話で、次の順に渡した。毎回、新しい会話にした。読者像(`reader.md`)はシステムプロンプトで渡した。

1. **題**: 題の感想と、結論の予想
2. **冒頭**: 本文の20%を超えた最初の段落の終わりまで。予想、根拠、自信、読みたいか、問い、題からの予想の変化、反応した文
3. **1段落ずつ**: 予想、前の段落からの変化、自信、問い、反応した文
4. **読後**: 実際の結論、外れたか、納得、要点、書き手、面白さ、読みやすさ、既読か

- 反応は5種類(驚いた、納得した、問いが解けた、迷った、手が止まった)で、文番号を挙げさせた
- 答えは JSON で返させた。1,870回のうち5回は JSON にならず、その段を空として扱った
- `measures.md` との違いは2つある。冒頭でも予想の変化と反応した文を聞いた。題なしの版は行わなかった

### 外した回

- 読後に「読んだことがある」と答え、題の頭4文字か書き手が合った回は、集計から外した
- 書き手は、A がブラッシュ、B が寺田、C が気象庁、D がやってみ太郎で照らした

## 10. AIの読者の指標(reader_metrics.py)

**なぜ要るか。** 読者の答えを、`measures.md` の「4. 役割の全う度合いを出す」の式で数にするため。

### 段と埋め込み

- 段は、題(k = −1)、冒頭(k = 0)、冒頭の後の段落(k = 1, 2, …)である
- 各回の予想の文を、ruri-v3-310m で埋め込みにする。プレフィックスは付けず、長さ1にそろえる
- 距離 d(x, y) = 1 − cos(x, y)

### 段ごとの量

N は集計に使った回数である。

- **予想の中心** cₖ = (1/N) Σ eₖ,ᵣ。eₖ,ᵣ は回 r の段 k の予想の埋め込み
- **予想の移動** Mₖ = d(cₖ₋₁, cₖ)。M₀ は題から冒頭への移動
- **跳ね比** Jₖ = Mₖ ÷ median(M₀, M₁, …)
- **予想の散らばり** Sₖ = 段 k の予想どうしの距離の平均(N(N−1)/2 組)
- **散らばり比** Vₖ = Sₖ ÷ median(S₀, S₁, …)。題の段も Vₖ を出すが、中央値には入れない
- **逆転率** Xₖ = 段 k で変化に「逆」を含む答えをした回の数 ÷ N

### 転の文の量

転は、AIの1回目が読み終えた後の役割で「転[全体]」とした文である。転の文 t がある段を k とする。

- **跳ね比** Jₖ、**逆転率** Xₖ
- **驚き率** = 転の文の前後1文のどれかを「驚いた」に挙げた回の数 ÷ N。どの段で挙げても数える
- **直前の散らばり比** Vₖ₋₁
- **先取り度** = ( d(c₀, t) − d(cₖ₋₁, t) ) ÷ d(c₀, t)。t は転の文の埋め込み。転が冒頭にあると出せない
- **順番の決まり** = Vₖ₋₁ < 1 かつ 先取り度 < 0.5 なら1、それ以外は0

### 文書の量

n は文の数である。

- **迷い率** = (1/N) Σᵣ ( 回 r が「迷った」に挙げた文の数 ÷ n )。同じ文は1回だけ数える
- **停止率**: 迷い率と同じ式で「手が止まった」を数える
- **要点の復元度** = (1/N) Σᵣ ( 1 − min_j d(要点ᵣ, 結論の候補ⱼ) )。結論の候補は、AIの1回目が「題の主張」「問いへの最後の答え」「書き手の結び」とした文
- **面白さ、読みやすさ、納得の点**: 読後の1〜5の平均と母標準偏差

### 判定

- 判定の式は「6. 判断を再現したかを判定する」と同じ
- 転が複数ある文書(D の書き直し)は、最大値を使う
- 転がない文書(C の原文)は、驚き率、逆転率、順番の決まりを0とし、跳ね比は「測れない」とする

## 11. 覚えていないかと τ の候補(memory.py、reader_metrics.py)

### 覚えていないか

- 題と冒頭(9 の冒頭と同じ範囲)を渡し、「続きを200字程度で書いて」と頼む。新しい会話で3回
- 原文の続き = 冒頭の後の本文から、空白を除いた先頭200字
- 5-gram の集合 G(x) = x の連続する5文字の並びの集合(空白を除く)
- **一致率** = |G(書かせた続き) ∩ G(原文の続き)| ÷ |G(書かせた続き)|

### τ の候補

- AIの1回目が「問い」とした文 q ごとに、q がある段と次の段で、読者が挙げた「いま抱いている問い」を集める
- q と各問いの cos を、ruri-v3-310m の埋め込みで出す
- 全文書の組を cos の小さい順に並べ、端から端まで等間隔に20組を選ぶ

### τ を決める(tau.py)

- 私が20組に ○(同じ問い)か ×(違う問い)を付けた
- 予測は「cos ≥ τ なら同じ問い」とする
- τ の候補は、隣り合う cos の中点と、両端の外側
- **一致** = 予測と私の判定が合った組の数。一致が最大の候補を τ にする
- **AUC** = (同じ問いの cos > 違う問いの cos になる組の数 + 等しい組の数 × 0.5) ÷ (同じ問いの数 × 違う問いの数)
- 結果: τ = 0.788、一致14/20、AUC 0.64

## 12. 構成の指標(graph.py)

**なぜ要るか。** 前回決めた2つの軸のうち、構成の軸を数字にするため。`measures.md` の「構成の側: グラフとして数える」の3にあたる。

- 関連は、AIが見分けた `relations.tsv` の1行である。範囲で書かれた文番号は、始まりの文を使う。題は0番とする
- **答えの先出し率** = (答えが問いより前にある「答える」の数 + 「先に明かす」の数) ÷ (「答える」の数 + 「先に明かす」の数)
  - 「先に明かす」は、題や見出しが先に言っているので、すべて先出しに数える
- **理由の先置き率** = 結が転より前にある「理由を渡す」の数 ÷ 「理由を渡す」の数
- **題からの先に明かす** = 題から出る「先に明かす」の数
- 判定は「6. 判断を再現したかを判定する」と同じ。答えの先出し率は、小さいほど面白い向き(g = −1)とする

## 13. 役割と関連の数(role_counts.py)

**なぜ要るか。** 跳ね比や先出し率のような2次集計の元になる、1次データを見るため。

- AIが見分けた結果(1回目と2回目)から、文書ごとに数える
- 役割の数 = 読み終えた後の役割にその役割を含む文の数。転は [全体] と [内側] を分けて数える
- 役割が変わった文 = 読んでいる時点の役割の集合と、読み終えた後の役割の集合が違う文の数
- 関連の数、特徴の数 = `relations.tsv`、`features.tsv` の、その種類の行の数
- 記事の図は、2回の平均を棒にし、「1回目/2回目」を数字で添えた(`images/make_figs.py`)

## 限界

- 見出しや表をどう文にしたかで、文の長さとサプライザルが変わる
- 出典のページが変わると、`prepare.py` で同じ本文を作れなくなる。今日の本文は `texts/` に残してある
- サプライザルの平均と標準偏差は、文ごとの値を同じ重みで扱う。短い文(見出しなど)の揺れが大きく効く
- rinna の窓をずらした文章では、文脈が N/2 トークンで打ち切られた部分がある
- 題のトークンは文脈には入るが、どの文の値にも入らない
- 全う度合いの指標は、AIの1回目の文の役割に依存する。A の書き直しと C の原文は、1回目と2回目で転の文が違った
- 既読の確かめで、題は最初に見せている。題が合うのは当然で、判定に使えない
- AIの読者を呼ぶ `claude -p` には、Claude Code のシステムプロンプトの一部が残る可能性がある。`--system-prompt` で置き換えたが、中身は確かめていない
