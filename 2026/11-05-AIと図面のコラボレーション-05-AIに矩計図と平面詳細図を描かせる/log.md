## 試したこと

#135 の平屋の図面一式（平面図・立面図・断面図）を渡し、実施設計の図面を描かせる。
描かせるのは、矩計図（外壁まわりの詳細な断面図）と平面詳細図（1/50 の平面図）。
DXF を直接書く方法と、#134 の MCP で LibreCAD を操作する方法を比べる。

## 結果

   - 最初は基礎上端を 340 に下げた。だが実務では、基礎の高さを先に決め、床の材料を積み上げて FL を出す。基礎は地面から 400 が一般的(フラット35の仕様)。

   - `make_house.py` に課題の ID `H-136` を足して作った。#135 の図面は変わらない。平面図も同じ。

   - 高さの名前(GL・FL・軒高)を添えたのは、DXF の Opus・Fable、Argon(2回とも)、Flash、MCP の Fable。

   - 建物の外(x=50,730)で測り、▽の高さの印を並べる: DXF の Fable。
   - 軒の出 600: 垂木の下面どうし(Opus 2回、MCP の Fable・Argon)、下面から上面の角へ(DXF の Sonnet・Fable・Argon、Flash)、屋根の上面どうし(MCP の Sonnet)。仕様は「垂木の先端まで」で、上下の角は決めていなかった。鼻隠しの外面や外壁の外面から測ったモデルはない。

## 学び

- 寸法は、数字が同じでも、どの部材のどの面を測るかで伝える意味が変わる。指示に数字だけ書くと、測る面はモデルが決める。測る面まで指示するか、測り方の見本を渡す。

- 寸法は、数字が合っていても、並べ方と CAD での見え方で読みやすさが変わる。図面を評価するときは、人が使う CAD の画面で見る。ezdxf の絵だけで判断すると誤る。

- 仕様の数値どおりに描けるかでは、上位のモデルはもう差がつかない。差は、読みやすさと描き込みの量に出た。ルールの採点に加えて、人が画像で見る必要がある。
- 描く前に止まるモデルと、仮に決めて描くモデルに分かれた。同じ指示文でも、「不足」を食い違いとみなすかどうかが違う。どちらがよいかは使う場面による。
- MCP は、作図の様子を見せられる代わりに、道具にない操作(寸法の文字の高さ、断熱材の模様)ができない。DXF を直接書く方法は、見えないが自由が利く。
- 道具の不具合(`set_vars` で図面が空になる)を、AI が自分で見つけて回り込んだ。回り込めた理由は、画面と状態を確かめる道具(doc_info、operation_log)があったため。
