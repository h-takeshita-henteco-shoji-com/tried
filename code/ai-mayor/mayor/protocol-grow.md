# 街を育てる期間の型(軽い型)

性格の違う市長を比べる前に、街を育てて出発点を作る期間の型です(#82)。
序盤はやることがほぼ決まっていて、性格の差が出にくいためです。
比べる本番では使いません。本番は `protocol.md` に従います。

この文書にないことは、`protocol.md` に従います。食い違ったら、この文書を優先します。

## 要点

- 目的は、街を早く大きくすること。目安は人口30,000以上
- 判断は月例だけ。見回りはしない
- 1回の呼び出しで6か月を運営する
- 見る道具は4つに絞る。画面写真は呼び出しの初めと終わりの2枚だけ
- 施策は月例で5件まで。建設費の上限は所持金の7割まで
- 時間は `advance(30)` で進める
- 効き目が分からない施策は、本番と同じく「試し」として打つ(`protocol.md` の3)

## 1. 1か月の流れ

なぜ見回りをやめるか: 育てる期間は、急ぎの件より大きく進めることを優先するためです。
`advance` はダイアログ(破産の警告など)が出ればその場で止まるので、急ぎの件は拾えます。

1. 月例の判断をする
2. `advance(30)` で次の月例まで進める

`advance` の turbo は使わない。人口9,000の街で測ると、turbo を4から16に上げても、10日の進みは25〜30秒で変わらなかった(計算が追いつかないため)。

## 2. 月例で見るもの

なぜ絞るか: 1か月の判断にかかる時間とトークンを減らすためです。

| 順 | 道具 | 見る点 |
|---|---|---|
| 1 | `city_info` | 人口、所持金、週の収支、需要、電気・水・下水が来ない市民 |
| 2 | `services` | 足りないサービス(電気・水・下水・ごみ・医療・教育・消防・警察) |
| 3 | `citizens_summary` | 失業と学歴、病人 |
| 4 | `complaints` | 困りごとの種類と場所 |

- 調べる道具(`buildings_near`、`zone_map`、`net_near`、`water_trace` など)は、必要なだけ使ってよい
- `citizen_voices` と `events` は見なくてよい
- 画面写真は、呼び出しの初めと終わりに `screenshot` で1枚ずつ撮る(ファイル名は `g<月>-town.jpg`)

## 3. 動かしてよい範囲

なぜ広げるか: 育てる期間は、答え合わせより成長の速さを優先するためです。

- 施策は、月例で5件まで
- 税は1回に±2ポイント、予算は±20ポイントまで(本番と同じ)
- 建設費の合計は、判断の時点の所持金の7割まで
- 維持費の増え分は、週の収支の黒字の範囲に収める(本番と同じ)
- 建てた後の確かめは、本番と同じく行う
- 試しは施策の5件の中で数える。試しの場所には、その月にほかの施策を重ねない

なぜ試しだけは本番と同じにするか: 育てる期間は答え合わせを軽くしています。それでも、効き目の分からない手を確かめずに続けると、成長が遅れます。
#107 では、停留所の効き目を確かめないまま、12か月バス路線を足し続けました。

## 4. 市政ノート

なぜ短くするか: 育てる期間のノートは、次の呼び出しの申し送りに使えれば足りるためです。

- 本番のノートとは別の `grow-note.md` に書く(置き場所は親が渡すフォルダ)
- 月例ごとに、数字の表に1行と、打った施策を箇条書きで書く。予想は1行でよい
- 答え合わせは、外れたものだけを書く。ただし試しの答え合わせは、当たっても書く(測る数を基準と比べる)
- ノートに「分からないことの一覧」を置き、本番と同じく更新する(`protocol.md` の3)。なければ、数字の表の後に作る
- 「〜を見てから」と書くなら、何を、どの道具で、どの範囲で、いつ見るかを同じ行に書く
- 呼び出しの終わりに、次の呼び出しへの申し送りを書く

## 5. 保存

- 呼び出しの初めと、3か月ごとの月例の初めに保存する。名前は `<運営の名前>-g<何か月目(2桁)>`(例: `fukuoka-grow-g03`)
- 人口が30,000を超えたら、その月例の初めの保存を出発点の候補として親に伝える
