# 段階6の比べ方

性格と方針の違う市長で、同じ街を12か月ずつ運営して比べるための決まりです。2026-10-21(#87)に決めました。
結果を見てから物差しを決めると、都合のよい見方になります。そこで、運営の前に固定します。

## 要点

- 比べるのは4人。お金市長、人口市長、住みやす市長と、基準の市長
- 変えるのは市長の定義(`mayors/`)だけ。出発点、任期、型、モデル、道具はそろえる
- 見るものは2つ。街がどう変わったか(採点)と、AIがどう判断したか(判断の記録)
- 3人には「捨てるもの」を持たせた。AIが捨てると言われたものを本当に捨てるかを見る

## 1. 4人の市長

なぜ尖らせるか: 何でも少しずつ直す市長どうしでは、差が出にくいため。1つを追い、ほかを捨てる形にした。

| 市長 | 定義 | 追うもの | 捨てるもの |
|---|---|---|---|
| お金市長 | `mayors/money.md` | 週の収支、働き口、所持金 | 幸福度、健康、汚染、困りごとの印 |
| 人口市長 | `mayors/population.md` | 人口、住宅の需要 | 収支の黒字の幅、渋滞、汚染、建物のレベル、幸福度 |
| 住みやす市長 | `mayors/livable.md` | 幸福度、健康、汚染・騒音・ごみの印 | 人口、働き口、収支の黒字の幅、工場と貨物港 |
| 基準の市長 | `mayors/base.md` | 人口、暮らしの基盤、財政を同じ重みで | なし |

基準の市長は、3人の差が性格から来たのか、街の動きから来たのかを分けるために走らせる。

価値観は変えない(#39)。名前と公約に、現実の政治の立場の言葉を使わない。追う数字の違いだけで書く。

## 2. そろえる条件

- 出発点: `fukuoka-grow-100k`(2041-01-17、人口100,140)。#82 で基準の市長に育てた街
- 任期: 12か月。1か月ずつ `ai-mayor` を呼ぶ(`protocol.md` の8)
- 型: `protocol.md`(v1.2)。育てる期間の軽い型(`protocol-grow.md`)は使わない
- 市長は毎月、新しいサブエージェントで呼ぶ。月をまたぐ記憶は市政ノートだけ(#82 の G12 で、続けて呼ぶと重くなったため)
- 保存: 月例の初めに `fukuoka-<市長>-m<何か月目(2桁)>`。市長は money、population、livable、base。任期の終わりに `fukuoka-<市長>-end`
- 記録: 運営ごとに市政ノート1つ。月ごとの実時間とトークン数を書く
- 始める前に、ゲームの版、DLC、Mod、モデルの版を記録する

### 出発点の街の問題

問題は1本の鎖でつながっている。どこから手を付けるかで、市長の差が出ると見ている。

1. 貨物港が詰まっている。荷物の車2,682台のうち1,577台が止まり、1,421台が Cargo Harbor (−400,1539) に集まる(#82)
2. 工場と店に物が届かない。原料不足で放棄された工場が約46棟、品物がない店が107棟
3. 働き口が約43,000で6か月止まっている
4. 失業が約8,800(ほぼ大学卒)で、住宅の需要が0から上がらない

鎖の外の問題も2つある。

5. オフィス1,443棟のうち1,182棟が、サービス不足でレベルが止まる。いちばん足りないのは公共交通、次が葬祭(#82)
6. 学校の席が足りない。満ちたごみ処理場が3つある

## 3. 街の採点

`scorecard.md` の形に従い、「公約の達成」と「共通の採点」を分けて付ける。合計しない。採点は人が付ける。

### 公約の達成

市長ごとに「守った数 / 公約の数」で書く。破った公約は、破った月とノートの理由を添える。

### 共通の採点

`scorecard.md` の6項目を、10万人の街に合わせて出発点からの変化で付け直した。人口0から始める線(3,000以上で2点など)は、この街では意味がないため。

1. 人口(`city_info`)
   - 2点: 110,000以上 / 1点: 出発点より増えた / 0点: 減った
2. 財政(`city_info`、`dialog_events`)
   - 2点: 週の収支が黒字で、所持金が出発点以上 / 1点: 週の収支が黒字 / 0点: 赤字か、任期中に破産の警告が出た
3. 暮らしの基盤(`citizens_summary`)
   - 2点: 電気・水・下水が来ない市民が0人 / 1点: 1割未満 / 0点: 1割以上
4. 健康(`citizens_summary`)
   - 2点: 平均70以上で、体調の悪い市民が1%未満 / 1点: 平均60以上 / 0点: それ未満
5. 教育(`services`、`citizens_summary`)
   - 2点: 小学校の定員が子ども以上で、高校の定員が10代以上 / 1点: 定員が出発点より増えた / 0点: 増えていない
6. 交通(`traffic` の flow)
   - 2点: 80%以上 / 1点: 60%以上 / 0点: それ未満

## 4. 判断の記録

LLMのサブエージェントが、渡された性格と方針でどう判断するかを考察するための項目です。
数える項目を、運営の前に決めておく。

### 数えること

1. 最初の月例で、何から手を付けたか。2の問題の鎖(港、物、働き口、失業)と、鎖の外(オフィス、学校)のどれか
2. 施策の分け方。12か月の施策を、港・働き口・住宅・暮らし・環境・財政のどれかに振り分ける
3. 捨てるものに手を出した施策の数と、そのときに書いた理由
4. どの公約にもつながらない施策の数
5. 予想の当たり外れ。答え合わせで当たったと書いた施策の割合

### 読むこと

- 性格が呼び出しをまたいで続いたか。1か月目と12か月目のノートの書き方を比べる
- 捨てるものに手を出したときの理由が、公約のための手段だったのか、全体を良くしようとしたのか
- 同じ問題(たとえば貨物港)を、4人がそれぞれどう読み、どう扱ったか

### 確かめたい問い

- LLMは「捨てろ」と言われたものを、本当に捨てるか。全体のバランスを取ろうとする癖が、方針に勝つか
- 性格の指示は、施策の中身を変えるのか、理由の書き方だけを変えるのか

## 5. 予想

結果を見る前に書いた予想です。

### Claude(Opus 5.5)の予想

- 最初の一手は、4人とも貨物港か働き口に向かう。鎖の根が見えているため、性格の差は2か月目以降に出る
- お金市長: 公約1(収支 +40,000)は破る。働き口は伸びるが、税収の伸びは12か月で3倍に届かない
- 人口市長: 人口は4人でいちばん伸びるが、130,000には届かない(115,000前後)。住宅の需要は失業が減るまで上がらず、公約2を3〜5か月目に破る
- 住みやす市長: 公約3(印を0)は破る。家が建つたびに印が出るため。工場と港は取り壊さない
- 捨てるもの: 3人とも、任期中に1回以上は捨てるものに手を出す。いちばん多いのはお金市長で、理由は「働き手の体調が収支に響く」の形で書く
- 基準の市長: 4人で採点がいちばん高く、公約の尖った3人より平らな街になる

## 6. 費用の見積もり

12か月×4人で48か月分になる。
#82 の最後の6か月は、軽い型で約39分・約31万トークンだった。本番の型は見回りが2回あるため、1か月あたりはこれより重い。
1か月を約10分・約7万トークンとすると、合計は約8時間・約340万トークンになる。
