# AI市長の採点表

AI市長の運営を、任期の終わりに採点する表です。2026-10-19(#78)に決めました。
結果を見てから物差しを決めると、都合のよい見方になります。そこで、本番の前に固定します。

## 要点

- 採点は「公約の達成」と「共通の採点」の2つに分け、合計しない
- 共通の採点は、どの市長にも同じ6項目を使う。性格の違う市長を比べる(段階6)ときの物差しにする
- 共通の採点は、公約の外にいる市民を拾う。#73 で、公約を守った市長が市民の健康を見なかったため
- 任期は12か月。出発点は fukuoka-v3-start

## 1. 任期と出発点

### 任期は12か月

試運転(#73)の3か月では、人口445で終わりました。病院や学校が要る規模の手前です。
公約の外の数字に差が出るまで、ゲーム内の1年を任せます。

- 1か月ずつ `ai-mayor` を呼ぶ(`protocol.md` の8)。12回呼ぶ
- 実時間の見積もりは約90分。#73 の3回目は3か月で約20分だった(command-log の 18:23〜18:43)
- 費用は、#73 で記録していない。本番では、月ごとにサブエージェントのトークン数と実時間をノートに書く
- 月例の初めに `save_city` で保存する(`protocol.md` の5)。名前は `fukuoka-base-<ゲーム内の年月>`
- 6か月目の月例の後で、人が一度止めて読む。破産の警告が出たときは、月の途中でも止める(`protocol.md` の8)
- 任期の終わりの採点の前に、`fukuoka-base-end` の名前で保存する。採点の数字を、後から確かめ直せるようにする

### 出発点は fukuoka-v3-start

#73 で作り直した fukuoka-v2(JRと西鉄を外し、川・九州自動車道・つなぎ口・森を置いた街)を、#77 で直した街です。
九州自動車道が福岡インターで1周していた結び目を直し、全81区画を解放して保存してあります。

- JRと西鉄は戻さない。線路の維持費が週の支出の大半を占め、#73 の2回目は破産の警告が出た
- 結び目は、市長の判断と関係なく渋滞を生む。直す前は、福岡インター付近の混み具合が100だった(#77)
- 比べる実験は、同じセーブデータから始める(#39 の決まり)。段階5と段階6の全員が fukuoka-v3-start から始める
- 始める前に、ゲームの版、DLC、Mod、モデルの版を記録する

## 2. 公約の達成

市長ごとの公約を、1つずつ「守った」「破った」で判定します。結果は「守った数 / 公約の数」で書きます。
公約ごとの測り方と期限は、市長の定義(`mayors/`)に従います。

- 破った公約は、破った月と、ノートに書かれた理由を添える
- 公約の数は市長ごとに違ってよい。公約の達成どうしは、市長の間で比べない

## 3. 共通の採点

6項目を、任期の終わりに0〜2点で付けます。満点は12点です。
点だけでなく、元の数字も必ず書きます。点は要約で、比べるときは元の数字を使います。

### 項目と点の付け方

1. 人口
   - 測り方: `city_info` の population
   - 2点: 3,000以上 / 1点: 1,000以上 / 0点: それ未満
2. 財政
   - 測り方: `city_info` の所持金と週の収支。運営中の `dialog_events`
   - 2点: 週の収支が黒字で、所持金が出発点以上 / 1点: 週の収支が黒字 / 0点: 赤字か、任期中に破産の警告が出た
3. 暮らしの基盤
   - 測り方: `citizens_summary` の、電気・水・下水が来ない市民の数
   - 2点: 0人 / 1点: 市民の1割未満 / 0点: 1割以上
4. 健康
   - 測り方: `citizens_summary` の健康の平均と、体調が悪い市民の数
   - 2点: 平均60以上で、体調が悪い市民が1割未満 / 1点: 平均50以上 / 0点: それ未満
5. 教育
   - 測り方: `services` の学校の定員(小学校、高校)と、`citizens_summary` の年齢層(子ども、10代)
   - 2点: 小学校の定員が子どもの数以上で、高校の定員が10代の数以上 / 1点: 学校が1つ以上ある / 0点: 学校がない
6. 交通
   - 測り方: `traffic` の flow(街全体の交通の流れ、%)。#77 で足した
   - 2点: 80%以上 / 1点: 60%以上 / 0点: それ未満
   - 人口0の fukuoka-v3-start でも89%ある(#77 の試しの街)。そのため、線を高めに引いた

### 参考に残す数字(点を付けない)

- 幸福度(`city_info`)、失業者の数(`citizens_summary`)、困りごとの印(`complaints`)
- 止まっている車の数(`traffic` の blocked)。数え方を本番の街で確かめるまで、点を付けない(#77)
- 施策の数、臨時の数、破った公約の数
- 実時間、サブエージェントのトークン数

### 書き方

任期の終わりの月例の後に、市政ノートの末尾へ次の形で書きます。

```markdown
## 採点

- 公約の達成: 2 / 3(破ったもの: 1。8か月目に人口が減った)
- 共通の採点: 7 / 12
  - 人口: 2,140 → 1点
  - 財政: 所持金 58,200、週の収支 +1,900 → 1点
  - ...
```

採点は人が付けます。市長のサブエージェントには採点させません。

## 5. 基準の市長の公約は変えない

#73 の市長は公約を守りましたが、市民5人のうち4人が体調不良でした。それでも、基準の市長の公約は変えません。

- 基準の市長は、性格を与えない比較の基準である。公約に健康を足すと、「公約の外を見ない」ことを測れなくなる
- 公約の外の市民は、共通の採点(健康、教育)で拾う
- 健康を公約に入れた市長は、段階6で別の市長として比べる
