# AI Mayor MCP のインターフェース設計

AI市長(Claude)が Cities: Skylines の街を見て、市長として操作するための道具の一覧。
Mod(`code/ai-mayor/src/`)が 127.0.0.1:8781 で HTTP の窓口を開き、MCPサーバー(`code/ai-mayor/mcp/server.py`)がそれを呼ぶ。

## 共通の決まり

- 座標はゲーム上のメートル。x が東、z が北。地図の中心が (0, 0)、端が ±8640。福岡のマップでは、ゲーム上の1m = 実寸2m
- 応答はJSON。成功は `ok: true`、失敗は `ok: false` と `error`
- ゲームの中身を読む処理はメインスレッド、作る・変える処理は計算スレッド(シミュレーション)で行う
- 建てるものは、ゲームの道具と同じく建設費を予算から払う(`pay=true` が既定)。人が置く骨格だけ `pay=false`
- 区画は最初から全81区画を持つ(#70 で決定)
- 解放の節目(マイルストーン)は確かめない。実際の市長には「人口が増えるまで建てられない施設」という制約がないため。区画と同じ考え方

## 呼んだ道具をゲーム画面に出す

AI市長が何をしているかを、ゲームを見ている人が追えるようにする。
MCPサーバーは道具ごとに、開始と終了を GET `/ui/command` で Mod に知らせる。
Mod はそれを貯め、ゲーム画面の左上のパネルに流す(新しいものが下)。

- 開始: `phase=start&id=..&tool=..&args=..`。引数は長いと途中で切る
- 終了: `phase=end&id=..&ok=true|false&detail=..`。成功は秒数、失敗はエラー文を出す
- 知らせが届かなくても、道具の処理は止めない(0.5秒で諦める)
- パネルはプレイヤーの操作を止めない。× で閉じても、次の道具が始まると開き直す
- ゲームの既定のフォントでは日本語が出ない恐れがあるため、パネルの見出しは英数字にする(未確認)

### 判断の理由とダイアログ

| 道具 | 窓口 | 内容 |
|---|---|---|
| `explain` | GET `/ui/note` | 判断を、パネルに白の「DO」(何をするか)と水色の「WHY」(なぜするか)の2行で出す。施策の前に呼ぶ |
| `save_log` | GET `/ui/log` | パネルのログファイルを、指定した場所に写す |
| `dialog` | GET `/ui/dialog` | ゲームに出ているダイアログの見出し、本文、ボタン。なければ null。最新の連番 |
| `dialog_events` | GET `/ui/dialog/events` | 指定した連番より後に開いたダイアログ。閉じたものも含む(最大50件) |

- Mod は Harmony で、ダイアログを開く関数(`UIView.PushModal`)と閉じる関数(`PopModal`、`PopAllModal`)に処理を差し込む。開いた瞬間に知らされる
  - 開いた直後は本文が空のことがあるので、次のフレームから文字を読む
  - Harmony がないときは、1秒ごとに見に行く。`/ui/dialog` の `harmony` で、どちらで動いているか分かる
- 開いたダイアログには連番を振り、履歴に残す。新しく出たら、パネルに橙色の「DIALOG」の行を足す
- `city_info` の `dialog` と `dialogSeq` にも載せる。見回りで必ず目に入るようにするため
- `advance` は、進める前の連番を覚えておき、連番が増えたらその場で止まる。進めている間に開いたダイアログを `dialogs` で返す。一瞬で閉じたものも拾える
- 試験用の窓口 `/ui/dialog/test` で、ゲーム内蔵のメッセージの窓を開ける(`close=true` で閉じる)。MCP の道具にはしない
- ボタンを押す道具は作らない。救済を受けるかどうかは、人が決める
- パネルは新しい行を上に出し、長い行は折り返す
- パネルに出した行は、テキストファイルにも書き足す。街を開くたびに新しいファイルを始める
  - 場所: `~/Library/Application Support/Colossal Order/Cities_Skylines/AIMayor/logs/<開いた日時>.txt`
  - 1行の形: 実時間、ゲーム内の日付、種類(OK / NG / DO / WHY / DIALOG)、内容をタブで区切る
  - 道具の行は、終わったときに成否つきで1行だけ書く

### マップエディター

人がマップを整えるための道具は、`editor-interface.md` にまとめた。AI市長には渡さない。

## 判断の単位との関係

判断の型は `code/ai-mayor/mayor/protocol.md`(#72)に書いた。月例(30日)、見回り(10日)、臨時の3種類。

## 数字の単位と、ゲームの癖

#77 で、ゲーム本体の処理を読んで確かめた。

- 維持費: ゲーム内部の値に 0.0016 を掛けると、週の支出と同じ単位になる(ゲームの画面と同じ計算)
  - 以前の `list_building_types` は内部の値を100で割って返していた(風力500)。週の支出では80。いまは `upkeepPerWeek` で週の値を返す
  - 確かめ: 給水塔を1基置くと、週の支出が240増えた。一覧の値と同じ
  - 建物の維持費は、予算の割合に比例して変わる。一覧の値は予算100%のとき
- カメラの角度: ゲームは引くほど角度を真下に寄せる。実際の角度 = 90 −(90 − 指定)× 2500 /(2500 + 引き)
  - 以前の `move_camera` は指定をそのまま渡していた。引き4000で45度を指定すると、実際は73度になった
  - いまは逆算して渡す。届かない角度(引き4000なら55度より浅い)は、届く一番浅い角度にして `notes` に書く
  - 地図の端の近くでは、カメラが地図の外に出ないよう、ゲームが見る場所をずらす。ずれは `current.offset`(m)で返す
- 交通の混み具合: 道路の区間ごとの `m_trafficDensity`(0〜100)。交通の情報画面の色と同じ
  - 止まっている車は、進めなかった回数(`m_blockCounter`)が32以上の車。ゲームは255に届いた車を消す

## まだ入れないもの

- 地区(ディストリクト)の線引きと、地区ごとの政策。線引きの塗り方を設計してから入れる
- 公共交通の路線(バスや電車の停留所と路線の設定)
- 読み込み。人が行う
- 取り壊しの払い戻し
