# マップエディター用インターフェースの設計

版: 1(2026-10-16、#73)。Mod と MCP に実装済み。エディターの中での動作は6章で確かめた。

## 結論

出発点のマップを人が整えるための道具を、Mod と MCP に足します。
足すのは、つなぎ口、天然資源、森林、水源、確認の5種類です。
AI市長(サブエージェント)には渡しません。マップは人が用意するもので、市長が変えるものではないためです。

## 1. なぜ要るか

2回の試運転で、出発点のマップに足りないものが2つ分かりました。

- 地図の外とのつなぎ口が、道路(九州自動車道)しかない。鉄道・船・飛行機で外と行き来できない
- 天然資源が水しかない。福岡にあるはずの森林と農地がない

どちらもマップエディターで人が手で置けます。
ただ、位置を地理院地図などの座標に合わせるには、手作業より道具のほうが正確です。#70 で骨格を Mod で置いたのと同じ考え方です。

## 2. 決まり

- 道具はマップエディターの中でだけ動く。ゲームの中で呼ぶと断る
  - 理由: 市長の運営中に、人や市長がマップの条件を変えられないようにする
- `ai-mayor` の道具の一覧には入れない
- 保存の道具は作らない。マップの保存は人がエディターの画面で行う(`protocol.md` の「保存は人が行う」と同じ)
- 座標はゲームと同じ。x が東、z が北、地図の中心が (0, 0)、端が ±8640

## 3. 道具の一覧

| 道具 | 窓口 | 内容 |
|---|---|---|
| `editor_state` | GET `/editor/state` | 今のモード、つなぎ口の数(種類と向きごと)、天然資源の合計、木の本数と上限 |
| `add_outside_connection` | POST `/editor/outside` | 線を引き、地図の端の点をつなぎ口にする |
| `paint_resource` | POST `/editor/resource` | 多角形の中のマスに、鉱石・石油・肥えた土地・砂の値を書く |
| `plant_forest` | POST `/editor/forest` | 多角形の中に木を植える。森林の値は、ゲームが木の本数から計算する |
| `resource_map` | GET `/editor/resource_map` | 天然資源の分布を画像にして保存する(確認用) |
| `add_water_source` | GET `/editor/water_source` | 水量と目標の水面の高さを数値で決めて、水源を置く |
| `list_water_sources` | GET `/editor/water_sources` | 置いてある水源の一覧 |
| `remove_water_source` | GET `/editor/water_source/remove` | 水源を取り除く |
| `carve_channel` | POST `/editor/carve` | 川筋に沿って地形を掘る。川底の高さを点ごとに決める |
| `restore_terrain` | GET `/editor/terrain/restore` | 最初に掘る前の地形に、まとめて戻す |
| `water_profile` | POST `/editor/water_profile` | 点ごとの地面と水面の高さ、水深をまとめて測る |
| `rebridge` | GET/POST `/editor/rebridge` | 既存の道路・線路の区間を橋に作り替える。川の線を渡すと、交わる区間をすべて作り替える |

### editor_state

マップの状態をまとめて返します。作業の前後に呼び、変わったかを確かめます。

- `mode`: MapEditor / Game など
- `outsideConnections`: 種類(Road、Train、Ship、Plane)ごとの、入りと出の数
- `resources`: 鉱石、石油、森林、肥えた土地、水の合計(ゲームの新規ゲーム画面の棒と同じ元の値)
- `trees`: 植わっている木の本数と、上限(262,144本)

### add_outside_connection

地図の外とのつなぎ口を作ります。

- 引数
  - `prefab`: 線の種類。例: "Train Track"、船の航路、飛行機の経路(名前は実装時にエディターの中で調べる)
  - `points`: 座標の並び。最初か最後の点は、地図の端から50m以内に置く
  - `direction`: in / out / both。一方通行の線(高速道路など)のときに使う
- 動き
  - 端に近い点を、地図の端の少し外(±(8640 + 線の半幅×0.8))へ動かす
  - その点に「外」の印(`NetNode.Flags.Outside`)を付ける。ゲームがつなぎ口の建物を自動で置く
  - 線は費用なしで引く。エディターで置いた線は、新しいゲームを始めるときに Original の印が付き、維持費がかからない
- 断るとき
  - 端から50mより遠い
  - ゲームの上限(1種類につき入り4・出4)を超える

### paint_resource

天然資源のマス(33.75m 四方、512×512)に値を書きます。

- 引数
  - `type`: ore / oil / fertility / sand
  - `polygon`: 座標の並び [[x, z], ...]。土地利用の公開データの多角形を、そのまま渡せるようにする
  - `amount`: 0〜255
  - `mode`: set(置き換え)/ clear(0にする)
- ゲームの決まりに合わせる
  - 森林のあるマスには、肥えた土地を書けない
  - 鉱石と石油、肥えた土地と砂は、同じマスで食い合う(エディターの筆と同じ扱い)
- 書いた後、ゲームに変更を知らせる(`AreaModified`)

### plant_forest

多角形の中に木を植えます。森林は塗れないためです。

- 引数
  - `polygon`: 座標の並び
  - `density`: 1マスあたりの本数(1〜5)。5本でそのマスの森林が最大になる
  - `prefab`: 木の種類。省くと温帯の木から選ぶ
  - `dry_run`: true なら植えずに、植える本数だけ返す
- 動き
  - 水の上、道路の上、建物の上には植えない
  - 上限を超えるときは植えずに断り、必要な本数を返す
- 気をつける点
  - 木は上限が26万本強しかない。福岡の山の森林を全部埋めると、上限を超える見込み
  - そのため、森林の多角形を選び、密度で調整する

### resource_map

天然資源の分布を、512×512 の画像にして保存します。

- 引数: `type`(ore / oil / fertility / forest / water)、`save_to`(PNG の絶対パス)
- 使い方: 土地利用の地図と並べて、塗った場所が合っているかを見る

### add_water_source

川に水を入れるための水源を、画面の道具より細かく置きます。

- なぜ要るか: 画面の道具の水量の最小(0.01)は、内部の値で655に当たる。小さく分けて置いてもあふれた(#64)
- 引数
  - `x`、`z`: 位置
  - `rate`: 水量(1〜65535)。画面の最小の数百分の1まで絞れる
  - `target`: 目標の水面の高さ(m)。水源は、水面がこれより低いマスにだけ水を足す。川岸より低くする
- 気をつける点: 川が海まで途切れずにつながっていないと、水は target の高さまでたまり続ける

### 川の検証(carve_channel ほか)

川が再現できるかを、エディターの中で試すための道具です。高さマップを作り直して読み込む代わりに、Mod から地形を直接掘ります。試すたびに人の操作が要らないためです。

- 川筋と川底の高さは `tools/river_line.py` で作る。河口から河川中心線をたどり、いちばん遠くまで続く道筋を本流とみなす
- 川底は、上流から河口へ下がるだけにする。河口側の低い区間は、海面より4m下げて海の水を入れる
- 検証の手順は `tools/river_trial.py` にまとめた(掘る、水源を置く、時間を動かして測る、元に戻す)

### 川の検証の結果(2026-10-16、那珂川)

エディターの中で、那珂川を1本だけ再現できた。

- 線: 河口から本流をたどり、ゲーム上で約4.1km(実寸約8km)。河川中心線のデータが中央の範囲しかないため、上流は途中で切れる
- 掘り方: 川底の幅64m、両岸32m。河口側の約2.5kmは川底を海面より4m下げ、上流は地面より4m下げた
- 潮の入る区間: 水源なしで、海の水が河口から2.5km上流まで入った。水深2〜4m。速度3で約1分
- 上流の区間: 上流の端に水源を1つ置いた。目標の水面は川岸の1.5m下
  - 水量50: 水源のまわりに約15cmたまるだけで、下流へ流れなかった
  - 水量400: 水源から海まで水がつながった。上流の水深は約1m。5分(ゲーム内で約9か月)動かしても、途切れもあふれも0
  - 水量1,200: あふれは0のまま。上流の水深が約1.5mに増えただけ。目標の水面が上限として効いた
- 両岸の外(中心から80m)には、どの水量でも水が出なかった

検証で分かった注意点:

- ゲームは、地形の更新を一度に約128点四方(約2km)までしか反映しない。広い範囲を一度に掘ると、一部しか下がらない。`carve_channel` は100点四方ずつに分けて知らせるよう直した(次の再起動で入る)
- 潮の入る区間と上流の境目に、約9mの段差ができた。水量400では、境目の数点がときどき浅くなる。川底を境目でなだらかにつなげば解ける見込み
- 川幅64mは、水平1/2縮尺の実寸で128m。那珂川の実際の川幅より太い

### 4本の川の検証(2026-10-16)

- 河口が海岸より陸側にあると、潮の入る区間に海の水が入らなかった。河口を、海に届くまで沖へ延ばして解いた
- 山あいでは、川の線と高さマップの谷底がずれ、水が溝からこぼれた。上流の点を左右80m以内の最も低い所へ寄せた
- 上流の端の水源1つでは、長い川の途中で水が途切れた。支流の合流地点(長さ1km以上の支流)に小さな水源(水量200)を足すと、ほぼつながった(途切れ: 那珂川1点、御笠川2点、室見川0点、多々良川6点)
- 元の地面が100mより高い山の区間は、川として掘らないことにした
- 合流地点の水源の目標を下げる(元の地面の3m下)と、途切れが大きく増えた。元の地面の1.5m下に戻した
- 「あふれ」と数えた点を画面で確かめると、水は川筋の中に収まっていた。曲がった所で、両岸の外の測る点が隣の川筋に重なっただけだった(測り方を直した)
- 那珂川を渡る道路を引くと、水の上の2区間が「Basic Road Bridge」になった
- 九州自動車道が多々良川をせき止めていた。道路は下の地形を平らにするため
  - `rebridge` に川の線を渡すと、御笠川と多々良川で1区間ずつ「Highway -> Highway Bridge」に作り替わった。掘り直すと、多々良川の途切れは0になった
- 試しのマップを保存して開き直すと、掘った地形、水、水源24か所、橋がそのまま残っていた
- 測り方を直した後、あふれは4本とも河口(海の中)の2点だけ。実際のあふれは0

## 4. Mod の変更

- `EditorApi.cs` を新しく作り、上の窓口をまとめた
- エディターでも、パネルと毎フレームの見張りを作るようにした(`LoadMode.NewMap` と `LoadMode.LoadMap`)
- 窓口の頭で `ToolManager` のモードを見て、MapEditor でなければ断る(`editor_state` だけはどこでも動く)
- 線を引く処理に、高さを固定する引数を足した(船の航路と飛行機の経路のため)
- 木を植える処理は時間がかかるので、計算スレッドを待つ時間を2分にした

## 5. 下敷きのデータ

位置合わせには、公開データを使います。取得のスクリプトは `tools/` に足します。

- 森林と農地: 国土数値情報の土地利用細分メッシュ(100m)。森林と田・畑のマスを多角形にまとめる
- 鉄道のつなぎ口: JR鹿児島本線が地図の外へ出る、北の端と南の端
- 船の航路: 博多湾の湾口から玄界灘へ
- 飛行機の経路: 福岡空港の滑走路の向き(北北西から南南東)に沿って、地図を横切る

データの出典と、公開してよいかは、取得のときに確かめます。

## 6. エディターの中で確かめたこと(2026-10-16)

- Mod の窓口は、エディターの中でもゲームの中身に触れた。`editor_state` は新規ゲーム画面と同じ値を返した(つなぎ口は道路の入り1・出1、資源は水だけ)
- 線の名前: 船の航路は `Ship Path`、飛行機の経路は `Airplane Path`
- つなぎ口は、端の区間を専用の線(`Train Connection Track` など)で引いたときだけできた。普通の線路(`Train Track`)では建物ができなかった
  - 専用の線で引くと、端に「Train Connection」の建物ができ、鉄道の入り1・出1と数えられた
  - 数は少し遅れて更新される。道具の戻り値の after は前の値のことがある。`editor_state` で確かめる
  - そこで `add_outside_connection` は、端に届く区間だけを専用の線で自動で引くようにした
- 分布の画像は北が上だった(博多湾が左上)
- 木を180本植えると、森林の値が9,180増えた(36マス×255)。肥えた土地も36マスに塗れた
- 水源は、エディターの時間を動かしているときだけ水を出した。水量5、目標を地面+0.5mにすると、水深約5cmで止まった

- 船と飛行機も、専用の線(`Ship Connection Path`、`Airplane Connection Path`)でつなぎ口ができた。高さは船が水面の40m、飛行機は440mで試した
- 試しのマップを保存し、そのマップから新しいゲームを始めて確かめた
  - つなぎ口は4種類(道路・鉄道・船・飛行機)とも、入り1・出1と数えられた
  - 森林9,180、肥えた土地9,180、木180本、水源1つが、そのまま残った
  - エディターで引いた線(線路、船の航路、飛行機の経路)は、すべて維持費なしの印が付いた
  - ゲームの中では、エディター用の道具は断った

## 7. まだ確かめていないこと

- 端に届く区間を専用の線で自動で引く直し(次の再起動で入る)
- 船の航路と飛行機の経路を、港や空港までどう引けば使えるか

## 8. 作る順番

1. `editor_state`(作業の前後の確かめに、最初に要る)
2. `add_outside_connection`(鉄道、船、飛行機)
3. `resource_map`(塗る前に、今の分布を見る)
4. `paint_resource`(肥えた土地)
5. `plant_forest`(森林)
