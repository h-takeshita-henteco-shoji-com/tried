# LibreCAD MCP に必要な機能(べき論)

AI に図面の読み取り・作図・修正を任せるために、MCP が持つべき機能の一覧です。
今の実装に縛られずに、#131 の課題と、これまでの回で分かったことから決めました。

## 実装の結果(2026-11-05)

一覧の機能を、楕円の詳細・線の太さ・人の操作の記録を除いて足しました。
寸法を描く、元に戻す、DXF を開くも、本体を改造せずに足せました。plugin から本体の内部の関数を直接呼んでいます(README の「本体の内部を呼べる理由」)。
「今」の列は実装後の状態です。「実現手段」の列は、計画時の見立てのまま残しています。

足したあとで分かった追加の検査があります。
stretch で、線の片端だけが窓に入ると、縦横の線が傾きます。validate に `skewed`(傾いた線)を足しました。

## 計画時の結論

- 一番足りないのは「確かめる」機能です。画面を見る、測る、検証する道具がありません
- 次に足りないのは、寸法とブロック(扉・窓などの部品)の読み書きです
- 寸法を描く、元に戻す(undo)は、plugin の API にありません。本体の内部を呼ぶか、本体の改造が要ります

## 優先度の決め方

- 必須: これがないと、#131 のどれかの課題を解けない
- 推奨: なくても解けるが、精度か手間が大きく変わる
- 任意: あると便利

## 実現手段の見分け

- API: plugin の Document_Interface にある
- 画面操作: 本体のメニュー項目(QAction)を plugin から押す。保存で使った方法
- Qt: plugin から Qt の部品を直接使う
- 内部: plugin から本体の内部の部品(RS_Document など)を呼ぶ。動くかは要調査
- 改造: 本体のソースを変えて組み立て直す

## 1. 接続と図面の状態

AI は座標の意味を知らないと、正しく読めないし描けないため。

| 機能 | なぜ要るか | 課題 | 優先 | 今 | 実現手段 |
|---|---|---|---|---|---|
| ping | 待ち受けているか確かめる | 全部 | 必須 | 済 | API |
| 図面の情報(単位、範囲、ファイル名、未保存か) | 単位と範囲が分からないと、座標を解釈できない | 全部 | 必須 | 済 | API(getVariable)+画面操作 |
| 操作の記録(誰が何をしたか) | 人と AI が同じ図面を触るため、変更の出どころを残す | #137 | 推奨 | 一部(AI の命令だけ) | Qt(plugin 内で記録) |

| 機能 | なぜ要るか | 課題 | 優先 | 今 | 実現手段 |

| 寸法の読み取り(測った値と、書かれた文字の両方) | #135 で、文字だけ古い寸法を見抜けなかった | #135 #138 | 必須 | 済 | 内部(要調査) |
| ブロックの読み取り(名前、挿入点、向き、中身) | 扉・窓・設備は部品(ブロック)で描かれることが多い | #132 #133 | 必須 | 済 | API(INSERT)+内部 |

## 8. 確かめる(ハーネス)

AI が自分の結果を確かめ、直すループを回すため。#135 の学びの中心。

| 機能 | なぜ要るか | 課題 | 優先 | 今 | 実現手段 |
|---|---|---|---|---|---|
| 画面の画像(全体・範囲) | AI が見た目で確かめる。#135 は CAD で開いて初めて気づいた | 全部 | 必須 | 済 | Qt(画面を画像にする) |
| 表示の操作(全体表示、範囲表示) | 画像を撮る前に、見たい所を映す | 全部 | 推奨 | 済 | 画面操作 |
| 検証(寸法の値と長さ、閉じた部屋、壁の切れ目) | 直し漏れを、ルールで見つけて差し戻す | #135 #136 | 必須 | 済 | server 側で計算 |
| 変更の差分(前後で何が変わったか) | 変えてはいけない所が変わっていないかを見る | #135 | 推奨 | 済 | server 側で計算 |

## 次に足す順番(案)

課題を解ける順に足します。

1. open / new、図面の情報、undo(既存の図面を扱い、失敗から戻るため)
2. 画面の画像、測る道具(AI が自分で確かめるため)
3. 寸法とブロックの読み取り(#132 #133 #138 と比べるため)
4. 円弧、属性の変更、stretch、寸法を描く(#135 #136 と比べるため)
5. 検証と差分(ループを回すため)
