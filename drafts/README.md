# drafts

次のテーマの構想を溜めておく場所です。
Issueに起票するほど形になっていない段階の材料を、ここで育てます。

## Issueとの使い分け

起票の前に、材料を育てる場所が要るためです。
Issueは「何を試すか」「なぜ気になるか」が言える段階のテーマを置く場所です。

- **drafts に置くもの。** 思いつき、参考のリンク、手本の画像、迷っている案の比較、長いメモ。
- **Issue に置くもの。** 何を試すかが1〜2文で言え、着手できるテーマ。

## 1構想1フォルダにする

参考画像やリンクを、構想と一緒に置くためです。

```
drafts/
├── README.md        この文書
├── _template.md     draft.md の雛形
├── archives/        終わった構想(フォルダごと移す)
└── 主題/
    ├── draft.md     構想のメモ
    └── assets/      参考画像、リンク集(必要なときだけ)
```

- フォルダ名は主題を短く(20字以内)。日付は入れず、`draft.md` の項目で持ちます。
- 新しい構想は `_template.md` を写して始めます。

## 起票したら

1. `/new-theme drafts/主題` で、`draft.md` を元にIssueを起票します。
2. `draft.md` の `status` を `起票済` にし、`issue` に番号を書きます。
3. フォルダは消さずに残します。構想の段階から追えるようにするためです。

見送った構想も消さず、`status` を `見送り` にして理由を1行残します。

## 終わったら archives に移す

`drafts/` 直下を、育てている途中の構想だけにするためです。
次の2つを「終わった構想」とし、フォルダごと `drafts/archives/` に移します。

- **起票したIssueがcloseした構想。** 親Issueなら、親がcloseした時点です。
- **見送った構想。** `status` を `見送り` にした時点で移します。

```bash
git mv drafts/主題 drafts/archives/
```

- `draft.md` の `status` と `issue` は書き換えません。
- フォルダ名は変えません。
- `/publish` でIssueをcloseしたときは、この移動を手順の中で行います。親を手でcloseしたときは、自分で移します。

## 注意

リポジトリは公開のため、drafts も公開されます。顧客案件に関わる内容は置きません。
