# 架空の訪問介護事業所の設計

作成日: 2026年11月8日(規模・加算・書類の見た目・対象月を、現実的な想定で決めた)

## この資料の結論

- 子テーマ10件で共有する、架空の訪問介護事業所を1つ作る。
- 規模は全国の平均に合わせる。利用者40人、延べ訪問は月約800回、職員は常勤換算で約7.6人。
- 特定事業所加算は区分IIを取る。訪問介護で最も多く取られている区分(算定率29.53%)。
- 書類は、実際の様式に近い見た目(PDF・Excel・紙の画像)でAIに渡す。正解は別にデータで持つ。
- 対象月は2026年9月。2026年6月の臨時改定の後で、2027年度の改定の前。

子テーマの一覧は `11-子テーマの案.md`、ペインは `03-ステークホルダー別ペイン.md` にある。

---

## 1. 何のための事業所か

10件の子テーマで、同じ事業所の書類を使い回すため。

- 子テーマを業務の流れの順に進めると、データも実際の業務と同じ順にたまる
- 不備やひっかけは、こちらで混ぜる。混ぜた箇所の一覧が、採点の正解になる
- 子テーマごとに、必要な利用者や書類だけを使えばよい。全部を毎回作り直さない

---

## 2. 事業所の設定

### 基本の設定

実在の事業所と取り違えないため、名前と所在地は架空にする。

| 項目 | 設定 | 理由 |
|---|---|---|
| 名前 | ためし訪問介護ステーション(架空) | - |
| 所在地 | 福岡県の架空の市(政令市・中核市ではない) | 指定権者を県にし、県の自主点検表と照らせるようにする |
| 指定権者 | 福岡県 | 同上 |
| 法人 | 小さな株式会社。訪問介護だけを営む | 倒産の多い小規模事業者に合わせる |
| 開設 | 2018年 | 処遇改善加算の経緯や、職員の勤続年数に厚みを出す |
| 対象月 | 2026年9月(請求は10月、入金は11月) | 臨時改定の後で、2027年度の改定の前 |

### 規模

全国の平均に合わせるため。

| 項目 | 設定 | 根拠 |
|---|---|---|
| 利用者 | 40人(要介護1〜5) | 延べ訪問と、1人あたりの訪問回数から逆算 |
| 延べ訪問 | 月約800回(1人あたり平均20回) | 1事業所あたり月807.6回(令和5年度 介護事業経営実態調査) |
| 職員(常勤換算) | 約7.6人 | 1事業所あたり7.6人(同上) |
| 訪問介護員(実人数) | 14人 | 1事業所あたり14.0人(令和5年度 介護労働実態調査) |

要支援(総合事業)の利用者は入れない。市町村ごとに基準や単価が違うため。

### 職員

| 職 | 人数 | 設定 |
|---|---|---|
| 管理者 | 1 | サービス提供責任者を兼ねる。常勤 |
| サービス提供責任者 | 2 | 管理者の兼務を含む。常勤。介護福祉士 |
| ヘルパー(常勤) | 3 | 介護福祉士2、実務者研修修了1 |
| ヘルパー(非常勤・登録) | 10 | 介護福祉士3、実務者研修2、初任者研修5。60歳以上が3人 |
| 事務 | 1 | 請求と総務を兼ねる。非常勤 |

- ヘルパーの実人数は、サ責2人を含めて14人
- 60歳以上の割合は、訪問介護員全体の25.7%に近づけた
- 資格の割合は、特定事業所加算IIの人材の要件を満たすように置く。要件の細部は、作るときに告示で確かめる

### 取る加算

現実によくある組み合わせにするため。

| 加算 | 取るか | 理由 |
|---|---|---|
| 特定事業所加算II | 取る | 訪問介護で最も多い区分。研修計画、会議、文書での指示と報告、健康診断などの体制の記録が要る |
| 介護職員等処遇改善加算 | 取る | ほぼ全事業所が取る。2026年6月以降の区分は、子テーマ10で決める |
| 初回加算 | 該当すれば取る | 新しい利用者が月に1〜2人入る想定 |
| 緊急時訪問介護加算 | 該当すれば取る | ケアマネの了承の記録が要る |
| 生活機能向上連携加算 | 取らない | 外部のリハ職との連携が要り、小規模では少ない |

### 外の登場人物

組織の境界(事業所とケアマネ)を作るため。

- 居宅介護支援事業所(架空)を3つ置く。1つはケアプランデータ連携を使い、2つはFAXで提供票を送る。導入率28%に近づけた
- 利用者のうち5人は、近くのサービス付き高齢者向け住宅(別法人)に住む。同一建物減算の境目には当たらない人数にする

## 3. 利用者の型

訪問の型ごとに、起きやすい不備が違うため。

| 型 | 人数 | 試す子テーマ |
|---|---|---|
| 身体介護が中心(入浴・排せつの介助) | 16 | 07、08 |
| 生活援助が中心(掃除・調理・買い物) | 12 | 01、07 |
| 身体と生活の両方 | 8 | 02、07 |
| 1日に複数回訪ねる(朝と夕など) | 4 | 08 |

ほかに、属性として次を混ぜる。

- 同居家族がいる人(生活援助の範囲が問題になる。01)
- 月の途中で状態が変わる人(計画の見直し。02)
- 9月に新しく入る人(初回加算。02、07)
- 9月に入院する人(キャンセルと欠員。04、09)

## 4. 書類

### 書類の見た目

実際の現場と同じ形でAIに渡すため。

| 書類 | 見た目 | 根拠の様式 |
|---|---|---|
| ケアプラン(第1〜3表) | PDF | 厚労省の居宅サービス計画書の標準様式 |
| サービス提供票と別表(第6・7表) | PDF。FAX派の2事業所の分は、FAXの画質の画像 | 同上 |
| 訪問介護計画書、手順書 | PDF | 国の様式はない。自治体の参考様式を参考にする |
| サービス提供記録 | 2種類。紙(複写式)を撮った画像と、記録アプリから出したCSV | 訪問系の介護ソフト導入率65.7%に合わせ、ヘルパーの3分の1を紙にする |
| 勤務形態一覧表 | Excel | 福岡県の様式を参考にする |
| 出勤簿 | CSV | - |
| 請求明細、給付管理票 | CSV(介護ソフトから出した想定) | - |
| 給与のデータ | CSV | - |
| 研修・会議の記録 | PDF | 特定事業所加算IIの体制の記録 |

- 様式は、厚労省の標準様式と自治体の参考様式をもとに作る。市販本や民間の様式は写さない
- 紙の記録の画像は、手書き風の字で作る。人の手で書くかは、量を見て決める

### 正解の持ち方

採点をプログラムで行うため。

- 正本はデータ(JSON・CSV)。AIに渡す書類は、ここから書き出す
- 混ぜた不備とひっかけは、別のファイルに一覧で持つ。AIには渡さない
- 単位数・2時間ルール・人員基準などは、プログラムで機械的に確かめる。このプログラムは、AIとの比べ役にも使う

## 5. 作り方

1. **正しい世界を作る。** 子テーマで使う分だけ、すべてが整合した書類を作る
2. **不備を混ぜる。** 子テーマごとの不備の一覧から選び、書類の一部を書き換える
3. **書類に書き出す。** データから、PDF・Excel・画像を作る

作る順は、子テーマの順(業務の流れの順)に合わせる。

| 子テーマ | 新しく作るもの |
|---|---|
| 01 | 利用者と家族の設定、契約書、重要事項説明書 |
| 02 | ケアプラン、訪問介護計画書、手順書、記録の一部 |
| 03 | 提供票(FAXの画像を含む) |
| 04 | ヘルパーの属性、利用者の位置、シフト |
| 05 | 勤務形態一覧表、出勤簿、資格証の一覧 |
| 06 | ヘルパーの話し言葉の台本 |
| 07 | 1か月分の記録、請求明細 |
| 08 | 1日に複数回の訪問の実績 |
| 09 | 1日の動き、給与のデータ、賃金規程 |
| 10 | 処遇改善の計画書と実績報告 |

## 6. 混ぜる不備の例

子テーマごとの不備は、各子テーマで決める。ここでは、運営指導の指摘でよく挙がるものを例として残す。

| 不備 | 子テーマ |
|---|---|
| 計画書の同意日が、初回の提供日より後 | 02 |
| ケアプランにない内容(通院の介助など)を提供し、請求した | 02 |
| 訪問介護計画の内容が、ケアプラン第2表とずれている | 02 |
| 予定の変更が、提供票か実績の一方にしか反映されていない | 03、08 |
| 勤務表にない人が訪問している。常勤換算の計算違い | 05 |
| 記録の時刻が欠けている。内容が定型文だけ | 07 |
| 記録は生活援助なのに、身体介護で請求した | 07 |
| 記録の所要時間と、請求の時間区分が合わない | 07 |
| 2時間空けずに訪ね、2回として請求した | 08 |
| 移動・待機の時間を労働時間に入れていない | 09 |

ひっかけ(不備に見えて正しいもの)も混ぜ、誤検知を測る。例外のルールは、告示と通知で確かめてから入れる。

## 7. 採点のしかた

### AIに出させる形

- どの利用者の、どの書類の、どの箇所か
- 何が食い違っているか
- 根拠(どの書類と比べたか、どのルールか)

### 比べる条件

- **書類だけを渡す:** AIが元から持つ知識で、どこまで見つけるか
- **ルールを引けるRAGを使う:** 子テーマ00で作る検索を使うと変わるか
- **ルールで調べるプログラム:** 数字の突き合わせはプログラムが強いはず。AIとの分担を見る

### 測るもの

- 不備の種類ごとの再現率
- ひっかけでの誤検知
- 根拠の正しさ

---

## 8. 注意

- すべて架空。実在の事業所・人名・住所と重ならないようにする
- 公開するときは、架空のデータであることを書類ごとに明記する
- 単位数や算定ルールは、この資料には書かない。作るときに、告示と通知の原文で確かめる
- 手元の解釈本は令和3年4月版。今のルールの確かめには使えない(`11` の「手元の解釈本の扱い」)
